How the privacy claim is verifiable

  • Nothing can be uploaded. A Content-Security-Policy of connect-src 'none' makes fetch, XHR, WebSocket and sendBeacon impossible from this page. Your images have no route out, whatever the code does.
  • Encoding is local. WebCodecs runs in your browser and the finished file is handed straight to a download. There is no server side to this app.
  • No third-party code. No CDN, no fonts, no analytics — every script and style is served from this site's own origin.
  • One deliberate exception. If you use "Add from a web address", that server is contacted to fetch the image and will see your IP address. Only images you paste in are ever fetched, and only inbound: img-src is opened, connect-src is not. The counter below lists every outside origin contacted.
  • It works offline. Disconnect from the network and everything except web-address loading still functions. That is the simplest proof of all.

Check it yourself. None of the above has to be taken on trust. There is no build step, so the files served to your browser are the source — view-source on this page, or read the repository:

github.com/your-name/images-to-video

The files worth reading first are index.html for the Content-Security-Policy, and src/encoder.js for the encoding loop that never touches the network.

1 Choose images

Add from a web address

This is the one feature that touches the network. Fetching an address tells that server your IP address and which image you asked for. The image is copied to local memory on arrival and never requested again. Nothing of yours is ever sent out — this page still cannot make an upload of any kind.

The server must permit cross-origin use of its images. Many sites do not, and those will fail with a message rather than silently breaking later.
