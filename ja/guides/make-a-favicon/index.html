16ピクセルでも読めるファビコンの作り方

ファビコンは、ロゴを小さくした絵ではありません。決まったサイズの絵の集まりで、ほとんどの人が開いたこともない入れ物に収められており、そのうちいちばん小さいものこそ、実際に誰もが目にするものです。ここでは、必要なサイズはどれか、その隣に置くファイルは何か、そしてロゴが縮小に耐えられなかったときにどうするかを説明します。

画像を ICO に を開く 画像を1枚入れれば、ブラウザや Windows や Mac が求めるすべてのサイズが出てきます。

最終更新 2026年8月20日

短い答え

画像を ICO に を開いて256ピクセル以上の正方形の画像を入れ、プリセットをウェブサイトのファビコンのままにして、favicon.ico をダウンロードします。それをサイトのルートに置き、https://yoursite.com/favicon.ico で応答するようにしてください。そのアドレスは、あなたの HTML が言及していようといまいと、どのブラウザも要求します。ですから厳密に必要なことは、ほかにありません。

以下は、技術的に存在しているだけのアイコンと、ちゃんと読めるアイコンとを分ける部分です。どのサイズが入るのか、iPhone と Android が代わりに何を求めるのか、そしてロゴが横幅16ピクセルに耐えられなかったときにどうするか。

1枚の画像ではなくサイズの集まりである理由

.ico ファイルは入れ物です。その中には、同じものを違う大きさで描いた完全な画像が複数入っていて、それを読む側が、必要な大きさにいちばん近いものを選びます。

無駄に聞こえますが、無駄ではありません。あなたのアイコンを16ピクセルで描くブラウザには選択肢が2つあります。あなたが描いた16ピクセル版を読むか、より大きなものをその場で縮めるかです。後者のほうが悪く、しかも目に見えて悪い — 細かいロゴを自動で縮めると粥になりますが、あなたが目で見た16ピクセル版は、単純化する機会があったものです。この形式が複数のサイズを抱えている理由は、その機会をあなたに与えるためです。

ウェブサイトの慣例は3サイズで、それぞれに理由があります。

  • 16×16 — ブラウザのタブ、アドレスバー、ブックマークのメニュー。人が見るのはこれです。ひとつだけ正しくできるなら、これを正しくしてください。
  • 32×32 — ブックマークバー、あなたのサイトへの Windows のデスクトップショートカット、そして高DPI画面のたいていのブラウザ。これらはタブのアイコンを32から描いて縮小します。
  • 48×48 — Google が検索結果のためにサイトのアイコンを読む大きさと、Windows の中アイコン表示。

それより大きいものは .ico の中ではなく、その隣の PNG に置くべきです。理由は下のモバイル向けファイルのところで出てきます。

16ピクセル問題

誰も警告してくれない部分がこれです。16ピクセルは、ふつうの画面で約4ミリメートル。全部で256個の点の格子で、この文の文字数より少ない数です。看板、名刺、ウェブサイトのヘッダーのために設計されたものが、そこまで縮められて生き延びることは、ほとんどありません。

消えるものを順に挙げます。

  • 文字。正方形に収めたワードマークは高さ3ピクセルほどです。小さな文字になるのではなく、灰色の帯になります。名前だけでなくシンボルも持つ企業のほぼすべてが、ファビコンにはシンボルだけを使う理由であり、シンボルを持たない企業が1文字を使う理由です。
  • 細い線。512ピクセルのロゴの上の1ピクセルの枠線は、16 ピクセルでは32分の1ピクセルです。縁に沿った薄い灰色のもやとして描かれるか、消えます。
  • グラデーションと影。移り変わるための場所がありません。やわらかい影は薄汚れた縁になります。
  • 細部の中の細部。文字の書かれた書類のアイコンは、にじみの入った長方形になります。

直し方は設定ではなく、別の絵を描くことです。1つか2つの形からなる単純化したマーク、高いコントラスト、そして1文字を超える文字は入れないこと。その版を意図して32か48ピクセルで描き、それを元にしてください。

道具にできるのは、公開する前にその問題を見せることです。 画像を ICO に のプレビューは、すべてのサイズを画面上の実寸で描きます。これを判断する唯一の方法がそれだからです — 16ピクセルのアイコンを64で表示すればきれいに見えますし、何も教えてくれません。

ロゴが正方形でない。余白か、切り抜きか？

アイコンは必ず正方形で、ロゴの多くはそうではないので、何かが起きるしかありません。答えは3つあり、しかも同じだけ良いわけではありません。

余白は画像全体を残し、その上下に空きを作ります。安全な既定値であり、横長のワードマークには間違った選択です。高さの3倍の幅があるものを正方形に収めれば、高さの3分の1を占めることになり、16ピクセルではロゴ5ピクセルと空白11ピクセルです。

中央で切り抜くのは、中央から最大の正方形を取ることです。組み合わせ — シンボルの横に社名が並んだもの — では、これが両方をまっすぐ断ち切ることがよくあります。それより、先に自分で元の画像をシンボルだけに切り抜いてから、それを変換するほうが良いです。

引き伸ばしは画像を潰して収めます。これが正しい状況はほとんどありませんし、用意されているのは主に、道具が黙ってそれをしていないと示すためです。

横長のロゴに対する一般的な答え。ロゴを変換しないこと。単独で成り立つ部分を変換すること。

透過か、単色の背景か

ウェブサイトにはたいてい透過が正解です。ブラウザのタブは、ブラウザとテーマによって灰色だったり白だったりほぼ黒だったりしますし、透過のアイコンはそのすべてに収まります。白い背景を塗り込んだアイコンは、暗いタブバーの中の白い長方形です。

知っておく価値のある例外が2つあります。

  • 暗いだけのロゴはダークモードで消えます。マークが本来白地に黒であるなら、透過ではなく色の付いた背景を与えるか、明るい輪郭線を付けてください。
  • Apple のタッチアイコンは不透明でなければなりません。 iOS はそれを自分の角丸のタイルに描き、透過を黒として描画します。そのファイルを作る道具は、あなたに代わってそれを平らにしておくべきです。ここの道具はそうします。既定では白に対してです。

ウェブサイトに必要な、.ico ではないファイル

favicon.ico はブラウザと Windows をカバーします。スマホはカバーしませんし、自作のアイコン一式はたいていここで早く止まってしまいます。ほかに3つのプラットフォームが、それぞれ独自の名前で独自のファイルを求めますし、そのどれも .ico の中を見ません。

  • iOS は、誰かがあなたのサイトをホーム画面に追加したとき、 180×180 の apple-touch-icon.png を読みます。それがないと、iOS はページのスクリーンショットを使いますが、それは失敗のように見えます。
  • Android と、すべてのインストール案内はウェブアプリのマニフェスト — site.webmanifest — を読み、それが 192ピクセルと512ピクセルの PNG を指しています。512は、ウェブアプリがスプラッシュ画面に表示するものでもあります。
  • Windows のスタートメニューのタイルは browserconfig.xml を読み、それが 150×150 の PNG を指しています。3つの中では重要度がいちばん低く、XML 4行です。

間違えやすいものがもうひとつあります。Android のランチャーは、アダプティブアイコンをスマホの好きな形 — 円、角丸の四角、丸みのある正方形 — に切り抜きますし、生き残ることが保証されているのは画像の中央80%だけです。端から端まで描かれたアイコンは四隅を失います。マスカブルアイコンとはそういうものです。同じ絵を意図して正方形の内側に小さく描いたもので、マニフェストの中で別途宣言されます。

画像を ICO に でウェブサイト用一式にチェックを入れると、これらすべてと、マニフェストと、それらを指す HTML のかたまりが出てきます。そのかたまりが意図的に省いているものがひとつあります。 favicon.ico のための <link> です。ブラウザはそのアドレスを自分で要求するので、併せて名指しすると、同じファイルが2度取得されてしまいます。

Windows のアプリケーションアイコンは別の一式

アイコンがサイトではなくプログラムのためのものなら、サイズが変わります。 Visual Studio が既定で用意する app.ico の中身は、16、32、48、256 です — シェルの3サイズに、スタートメニューとエクスプローラーの特大表示が描画に使う大きいものが加わります。

高DPIのディスプレイでは Windows は20、24、40、64、96も求め、なければ手持ちのいちばん近いサイズから作り直します。それが問題になるかどうかはアイコン次第です。平坦な形なら作り直しに耐えますが、細かいものは耐えません。それらを足すとファイルはおよそ2倍になりますが、アプリケーションにとってそれは何でもありません — 訪問者全員が取得するファビコンとは、計算がまったく違います。

大きさについてもうひとつ。容量があるのは256のエントリです。非圧縮で保存するとそれだけで264 KB、アイコンの中に PNG として保存すればたいてい30未満です。 PNG のエントリは Windows Vista 以降なら読めるので、避ける理由は、本当にそれより古いソフトか、アイコンを自分で解析するインストーラーや組み込みの道具だけです。

Mac はまったく別のファイルを読みます

アイコンが Windows ではなく Mac のアプリケーションのためのものなら、上のことは何ひとつ当てはまりません。macOS は .ico をまったく読まないからです。読むのは .icns で、同じ考えを別の包みに入れたもの — 1つの入れ物に複数のサイズ — ですが、知っておく価値のある違いが3つあります。

  • サイズは固定です。Apple が10個の枠を公開しており、選ぶものはありません。16、32、64、128、256、512、1024ピクセルで、32と256と512は 2度ずつ登場します。それぞれが独自のサイズであると同時に、1段下のサイズの Retina 版でもあるからです。
  • 1024まで上がります。.ico は256で止まります。 Mac のアイコンファイルが数百キロバイトで、ファビコンが15キロバイトなのはそのためです。一度配るアプリケーションにとってそれは何でもありません。訪問者全員が取得するのはファビコンだけです。
  • 1024ピクセルに耐えなければならないのは、あなたの図版のほうです。 2つの問題は同じ絵の両端です。ファビコンは極小でも成り立たねばならず、Mac のアイコンは巨大でも持ちこたえねばなりません。512で書き出したロゴを1024に引き伸ばすと、Retina ディスプレイではぼやけて見えますし、App Store は受け付けません。

使い方。アプリケーションバンドルは YourApp.app/Contents/Resources/ にそれを置き、 Info.plist で名前を指定します。フォルダーやディスクイメージには、 Finder で .icns を選んで Command-C を押し、変えたいものの「情報を見る」を開き、左上の小さなアイコンをクリックしてから Command-V を押してください。

画像を ICO に で macOS アイコン にチェックを入れると、Windows 用のファイルを添えても添えなくても、それが書き出されます。両方のプラットフォームに配るものは両方を必要としますし、両方が同じ画像から、同じ一度の処理で描かれます。

うまくいったかを確かめる

ブラウザはファビコンを、ほとんど何よりも強くキャッシュします。ですから「アップロードしたのに何も変わらない」は、たいてい間違いではなくキャッシュです。またファイルを編集し始める前に、試すべきことが2つあります。

  • https://yoursite.com/favicon.ico を直接開いてください。ファイルがダウンロードされるなら、それはそこにあり、あなたが見ているのはキャッシュです。 404 が返るなら、ルートに置かれていません。
  • プライベートウィンドウでサイトを読み込んでください。たいてい独自のアイコンのキャッシュを持っています。

Windows では、.ico をフォルダーに入れてエクスプローラーの表示サイズを切り替えることで確認できます。小、中、大、特大は同じファイルから違うエントリを描くので、システムが見るとおりにそれぞれを見られます。

Mac では .icns がプレビューで開き、横にすべての枠が並びます — 同じ手が Finder でも使えます。フォルダーに入れて、表示オプションのサイズのスライダーをドラッグすれば、中の絵が入れ替わるのを見られます。

これにアップロードは要りません

画像の拡大縮小は、どのブラウザも何年も前からしていることですし、 .ico は6バイトのヘッダーと、画像1枚につき16バイトと、そして画像そのものです。それを作る工程に、サーバーを必要とするものはありませんし、ここの道具は使っていません。ページの Content-Security-Policy は接続してよいアドレスをすべて挙げていますが、そのどれも当サイトのものではありません。

ここではそれを、ふつう以上に気にする価値があります。無料のファビコン生成サイトに渡されるロゴは、しばしば未発表のブランドです — アイコンは最初に作られるものの1つで、最後に発表されるものの1つだからです。言われるより確かめたい方は、ページを読み込んでから回線を抜き、それでも作ってみてください。 オンライン変換サイトにファイルをアップロードしても安全ですか？ には、どの道具にも試せる確認方法がさらに3つ載っています。
