# ファイルのコピーはどこへ行く？

ローカル処理はツールの中で起きることを表します。保存、同期、共有したコピーには、それぞれ別の行き先があります。私的情報のない配布資料を追い、その境界を確認します。

最終更新 2026年10月22日

## 私的な情報を含まないファイルで始めます

ローカル処理とは、ツールがファイルをどこで処理するかを表します。保存した出力がその後どう扱われるかは、ブラウザの保存先、クラウド同期ソフト、バックアップ設定で決まります。ツールを閉じても、それらのコピーは管理されません。[処理のためのアップロードに関するガイド](https://abox.tools/ja/guides/is-it-safe-to-upload-files/)は最初の境界を説明しています。このガイドでは保存後のファイルを追います。

架空の予定表と絵だけが入った`workshop-handout.pdf`を考えます。小さくした版を`workshop-handout-small.pdf`として書き出し、その結果をイベント用フォルダへコピーします。バックアップを数える前から、原本、ダウンロードした出力、別に保存したコピーがあります。

同様に私的な情報のないファイルを使い、自分の設定を調べてください。役立つコピーがどこにあり、どのアカウントや端末からアクセスでき、どの途中のファイルが役目を終えたのかを把握するのが目的です。

## ダウンロードした出力を探します

ファイルマネージャーで書き出したファイルを探し、フォルダの完全な場所を記録します。名前や、ブラウザで開いたという事実だけから保存場所を推測しないでください。

Chromeでは、既定のダウンロードフォルダを選ぶか、保存先を毎回尋ねる設定にできます。既定では通常ユーザーのダウンロードフォルダですが、設定で変わります。Googleの[ダウンロードの説明](https://support.google.com/chrome/answer/95759?hl=en)では、ブラウザの記録とファイルを区別しています。履歴から項目を取り除いても、保存されたファイルはコンピューターに残ります。

この例では`Downloads/workshop-handout-small.pdf`を記録します。別の場所へコピーしたなら、その場所も別に記録してください。どちらかが不要だと判断する前に、両方を開いて確認します。

## 保存先フォルダが同期されるか確認します

ファイルマネージャーに見えるフォルダが、クラウドアカウントにつながっていることもあります。「ドキュメント」ならこのコンピューターだけにあると思い込まず、実際の場所と同期アプリの設定を確認してください。

OneDriveは選んだフォルダをバックアップし、他の端末でも内容を利用できるようにします。Microsoftの[フォルダのバックアップ説明](https://support.microsoft.com/en-us/onedrive/back-up-your-folders-with-onedrive)に、対象フォルダの確認方法があります。この機能を設定した場合の動作であり、すべてのドキュメントフォルダが自動で同期されるわけではありません。

イベント用フォルダが、OneDriveにバックアップされるドキュメントフォルダの中にあるとします。クラウドアカウントを一覧へ加えてください。共有設定も確認します。ファイルがある場所と、誰がアクセスできるかは別の問題です。

## コピーの簡単な一覧を作ります

実際に見つけたものを記録し、不明な場所は確認対象として印を付けます。自分の環境では、この例より項目が少ないことも多いこともあります。

| 場所とコピー | 判断すること |
| --- | --- |
| プロジェクトフォルダ：元の配布資料 | 後から変更するなら残します |
| ダウンロード：小さくした出力 | 採用したイベント用コピーを確認してから見直します |
| イベント用フォルダ：確認済みの出力 | イベントで使うコピーとして残します |
| クラウドアカウント：同期が有効ならそのフォルダ | アカウントと共有アクセスを確認します |
| バックアップ：保存されていれば以前の版 | 目的と保存期間を確認します |
| ごみ箱：保持されていれば削除した出力 | 関係する項目だけを確認します |

名前が同じでも、二つのファイルが同じ版とは限りません。途中の出力を削除する前に内容を確認し、使うコピーを特定してください。

## バックアップと以前の版も含めます

バックアップは、作業中のファイルを失ったり変更したりしても、内容を永久に失わずに済むようにするものです。役立つ保護であり、現在の版を置き換えた後も古い版を取り出せる場合があるということです。

Windowsのファイル履歴は、設定すると外付けドライブやネットワークの場所へ版を保存できます。対象範囲と復元の動作は、Microsoftの[ファイル履歴を使ったバックアップと復元](https://support.microsoft.com/en-us/windows/experience/backup-recovery/backup-and-restore-with-file-history)で説明されています。

バックアップの対象フォルダと、版の保存期間を確認します。一つの文書を片付けるためにバックアップフォルダを削除せず、その情報を記録してください。無関係な作業の、唯一復元できるコピーが入っているかもしれません。管理対象のコンピューターでは、保存期間の変更や記録の削除に組織の手順を使ってください。

## 削除操作が何を変えるか理解します

操作によって影響する場所は異なります。OneDriveでファイルをオンライン専用にすると、端末のダウンロード済み内容を取り除き、クラウドのファイルは残します。同期ファイルを削除すると、クラウドや他の同期端末にも影響する場合があります。Microsoftの[ファイルオンデマンドの説明](https://support.microsoft.com/en-us/onedrive/save-disk-space-with-onedrive-files-on-demand-for-windows)に違いが記載されています。コピーを管理する操作は、作用を確認してから使います。

削除済みファイルも復元できる場合があります。OneDriveには独自のごみ箱があり、保存期間はアカウントの種類と設定によります。クラウドだけにあるファイルは、コンピューターのごみ箱に現れるとは限りません。Microsoftの[削除したファイルの復元説明](https://support.microsoft.com/en-us/onedrive/restore-your-onedrive-files)を参照してください。

見えている一つのフォルダからファイルを取り除いて分かるのは、その場所で何が起きたかだけです。別の出力、バックアップ、すでに他の人へ渡したコピーまで消えたことにはなりません。

## 残すものを選び、確認します

ワークショップの例では、今後の編集に必要な原本と、確認済みのイベント用コピーを残します。残す出力が正常に開くと確認してから、余分なダウンロードを見直します。役立つバックアップは予定した保存方針で保持し、分からない項目は理解するまでそのままにします。

- 残すと決めたファイルを開き、内容を確認します。
- フォルダ、クラウドアカウント、共有設定を確認します。
- 操作の影響を確認してから、役目を終えた特定のコピーだけを取り除きます。
- まだ調べる必要があるバックアップや場所を記録します。

次に書き出すときは、保存先を意識して選び、分かりやすいファイル名を付けます。原本、試した版、最終出力の区別を覚えているうちに、作業の終わりでもう一度この確認を行ってください。
