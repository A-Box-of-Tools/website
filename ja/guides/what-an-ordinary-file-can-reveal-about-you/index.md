# 普通のファイルから分かる個人の情報

パスワードや機密の表示がないファイルでも、個人のことが分かる場合があります。どのコピーを共有するか決める前に、内容、文脈、相手を確認します。

最終更新 2026年10月22日

## ファイルを受け取る人から考えます

ある相手に適切なファイルでも、別の相手には情報を伝えすぎる場合があります。経費の確認担当者には領収書の日付と店名が必要かもしれません。一方、価格についての公開の質問を読む人には、会員番号や訪問した正確な時刻は通常必要ありません。

確認するのは氏名だけではありません。相手がすでに持つ情報と細部を組み合わせることで、個人が分かる場合があります。英国の情報コミッショナーオフィスは、[個人情報のガイド](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/personal-information-what-is-it/what-is-personal-information-a-guide/)で、このように状況が関わる点を説明しています。

以下は架空の例です。それぞれ共有する理由から始め、ほかに何が一緒に渡るかを考えます。

## 領収書が伝えるのは価格だけではありません

North Street Printの領収書を考えます。CAD 12.40の購入、支店の住所、時刻、会員番号、顧客のメールアドレスが載っています。これを、印刷費用について話す地域の公開の場に投稿したいとします。

費用は品目、数量、価格で説明できます。メールアドレスは取引と個人を結び付けます。支店と時刻からは、いたかもしれない場所と時間が伝わります。会員番号は、その話に不要な識別情報を加えます。

それで本人の習慣が証明されるわけではなく、本人が注文を受け取ったかどうかも分かりません。文書に書かれた事実と、読み手が推測することを分けてください。一度の購入だけでは、その人の日常を確かに説明できません。

公開の話し合いには、価格を理解するために十分な情報を含むコピーを用意します。経費精算では、確認担当者が求める取引の詳細を残します。共有用コピーの作成で自分の記録を失わないよう、原本は別に保管してください。

## スクリーンショットには周囲も入ります

文書のアップロード中に起きたエラーのスクリーンショットを考えます。エラーの周りには、アカウントのメールアドレス、求人応募のブラウザタブ、同僚からの通知、顧客名を含むファイル名があります。

サポート担当者には、何が失敗したかを伝える必要があります。ファイル名は形式の説明に役立つかもしれませんが、顧客名は役に立たないかもしれません。通知は無関係です。公開フォーラムの読者は、個別のサポート会話より広い範囲に及びます。

エラーだけを見ず、スクリーンショットを端から端まで読んでください。タブのタイトル、サイドバー、アカウントメニュー、ファイル名、アドレス、通知を確認します。エラーメッセージ、関係する操作部分、拡張子など、問題を説明する細部を見分けてください。

その文脈は残します。説明のないエラー番号だけにすると、画像が役に立たなくなり、追加情報を求められることがあります。

## 出席者名簿は関係性を示します

架空のワークショップの表に、氏名、連絡先、出欠、欠席理由のメモが入っています。主催者は欠席者へ連絡する必要があります。資金提供者は、何人参加したかを尋ねています。

目的は別々です。主催者には個別の記録が必要かもしれません。資金提供者が人数を尋ねたからといって、全員の住所や欠席理由まで必要になるわけではありません。記名の一覧は、作成者が重要だと思うかどうかにかかわらず、人と行事、場所、日付を結び付けます。

氏名だけを取り除いても、人物が分かる組み合わせが残る場合があります。特定の職場から来たボランティアが一人だけだと皆が知っていれば、その説明も本人を指します。列を削除すれば匿名になると思い込まず、集計結果を確認してください。他の人の情報も、自分の情報と同じくらい丁寧に確認します。

## ページに見えるものの外側も調べます

一部のファイル形式では、見える内容は全体の一部です。Microsoftは、Officeファイルに作成者のプロパティ、コメント、変更履歴、非表示の表計算内容が含まれ得ると説明しています。非表示のワークシートも、相手が受け取るファイルに含まれる場合があります。Microsoftの[ドキュメント検査の説明](https://support.microsoft.com/en-gb/office/collab-files/remove-hidden-data-and-personal-information-by-inspecting-documents-presentations-or-workbooks?nochrome=true)を参照してください。

撮影時に記録されていれば、写真には位置のメタデータが含まれることがあります。Appleは[位置メタデータの説明](https://support.apple.com/en-gb/guide/personal-safety/ips0d7a5df82/1.0/web/1.0)で、その情報を含む写真の受信者は撮影場所を知る可能性があると説明しています。

適切なビューアーか、作成元のアプリで実際のファイルを調べます。すべての写真に座標があり、すべての文書に隠れたコメントがあるという意味ではありません。何が入っているかを確認してください。形式ごとの詳しい説明は、[PDFが記憶するもの](https://abox.tools/ja/guides/what-a-pdf-remembers/)と[写真のメタデータ](https://abox.tools/ja/guides/remove-exif-and-gps-data/)のガイドにあります。

## 編集前に短い確認計画を作ります

1. **目的を書きます。**この相手は、このファイルで何をする必要があるのかを一文にしてください。ある細部が役立つか判断できる程度に具体的にします。
2. **相手の範囲を決めます。**一人の確認担当者、チーム、公開ページを区別します。受信者が他の人へ渡す想定かも考えてください。
3. **含まれるものを挙げます。**見える内容、ファイル名、文書のプロパティ、形式が扱える追加の内容を調べます。
4. **組み合わせを考えます。**これらの細部と相手がすでに知る情報を結び付けると、何が分かるか考えます。
5. **残すものと消すものを示します。**証拠を理解するために必要な細部は残します。重要な内容を削る前に、曖昧な要件を確認してください。
6. **最終コピーを確認します。**実際に送るファイルを開き直します。相手の問いにまだ答えられることと、変更が出力に反映されたことを確認します。

## 目的を果たすのに十分な情報を残します

目指すのは、役に立ち、目的に見合った共有用コピーです。ICOの[データ最小化の説明](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-protection-principles/a-guide-to-the-data-protection-principles/data-minimisation/)は、情報を絞ることと、示した目的に十分な量を残すことのバランスを扱っています。目の前のファイルと相手に、その確認の考え方を当てはめてください。

価格には数量と通貨を、エラーには診断に必要な文脈を、出席者の合計には対象の行事と日付を残します。何を残すべきか分かったら、適切な編集ツールやメタデータツールを選びます。画像については、[黒塗りのガイド](https://abox.tools/ja/guides/redact-an-image/)で削除と出力確認を説明しています。共有前に最終ファイルを計画と照合してください。
