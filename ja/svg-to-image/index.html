描画は、いまその絵をあなたの画面に出したのと同じエンジンが行います。あなたのファイルはディスクから読み出され、そのルートタグが、あなたが読める src/svg.js の100行ほどによって指定サイズに書き換えられ、ブラウザにすでに入っているキャンバスに描かれます。このツールにはネットワーク機能が一切ありません — 取りに行く先も、送る先もありません — 仮に送ろうとしても、このページの向こう側にロゴを受け取るサーバーは存在しません。

この主張をどう確かめられるか

  • あなたの図版には出ていく先がありません。 Content-Security-Policy はこのページが接続してよいアドレスをすべて挙げていますが、そのどれも当サイトのものではありません。あなたのファイルを集めるための受け口はここにはなく、あったとしても送るコードがありません。
  • ここには何かを取りに行くコードがありません。 src/ のどこにも fetch も XMLHttpRequest も sendBeacon もありません。描画処理の全体は、あなた自身のファイルの blob を抱えた <img>、キャンバスへの drawImage ひとつ、そして canvas.toBlob ひとつです。
  • SVG は文書であり、これはそれが何もできないモードです。 SVG は <script>、外部の <image href="https://…">、スタイルシート、ウェブフォントを抱えられます。<img> を通して描かれると、仕様が secure static mode と呼ぶ状態に入ります。スクリプトは走らず、それらのアドレスはひとつも取得されません。これは私たちの約束ではなくブラウザの保証であり、このページが見たこともないファイルを、そのファイルに外部へ連絡させることなく開ける理由です。
  • Google が読み込むもの、そして渡されないもの。 広告と計測のスクリプトは Google から、寄付ボタンは Buy Me a Coffee から来ています。そのどれにも、あなたの図版に関する情報は渡されません。ファイルを読み、サイズを決め、描くコードはすべてこのオリジンから配信され、リポジトリに載っています。
  • オフラインで動きます。 通信を切ってもこのツールは何も変わりません。もともと通信する段階が存在しないからです。これがいちばん単純な証明です。

ご自分で確かめてください。以上のどれも、鵜呑みにしていただく 必要はありません。このページは、リポジトリ内のテンプレートと設定から、あなた が読んで自分で実行できるビルドスクリプトによって生成され、その結果が dist ブランチに置かれています — つまり、配信されている ものと、ソースをビルドした結果とを差分で比べられます:

      SVG をアップロードせずに PNG に変換する手順

      1. SVG を選びます。 選択欄にドロップするか、フォルダーごと選んでまとめて変換してください。ブラウザがディスクから直接読み出します。その間に何かがどこかへ送られることはありません。各行には、そのファイルが自分を何ピクセルだと思っているかが表示されます — そのサイズが viewBox から来た場合や、ファイルが何も宣言していないので仮定した場合には、そう書き分けます。
      2. 大きさを指定します。 ファイル自身のサイズに対する倍率がいちばん手早く、まとめて処理する場合の正解です。どの図もそれぞれの出発点から拡大されるので、アイコン一式なら比率が保たれます。そうでなければ、幅、高さ、長辺、あるいは両辺を指定した枠で決めてください。ここでは大きな数値を指定しても、写真のような代償はありません — 図はその大きさで描き直されるのであって、引き伸ばされるのではないからです。
      3. 必要なら高DPI用の複製も作ります。 スマホや Retina のノートPCは、 CSS の1ピクセルに対して2から3の実ピクセルを描くので、200ピクセルのロゴには 400または600ピクセルのファイルが必要です。@2x と @3x を指定すれば、Xcode も Android のツールも CSS の image-set() も期待する名前で出てきます。しかもそれぞれ、別々に丸められるのではなく、最初のものの正確に2倍・3倍です。
      4. 形式を選び、透過をどうするか決めます。 理由がなければ PNG です。可逆で、透過を保ち、平坦な色がよく圧縮されます。JPEG には透過がまったくないので、選んでも選ばなくても背景色が塗られます — それがなければ透過だったピクセルはすべて黒くなります。WebP は両方に対応し、ファイルも小さくなりますが、それを読めないほど古いソフトが代償です。
      5. ダウンロードの前にプレビューを見てください。 プレビューは、ファイルを書き出すのと同じコードが、あなたのファイルから、あなたの端末で描いたものです。図がピクセルになるときに変わるものは2つあり、どちらもここに現れます。幅が半ピクセルだった髪の毛のような線は灰色になり、文字はウェブから取ってきたのではなく、このコンピューターにあるフォントで描かれます。
      6. ファイルを受け取ります。 1ファイルにつき1つのダウンロード、またはまとめて1つの zip です。名前は元の SVG に従い、複製には @2x や @3x が付きます。同じ名前になってしまう 2つのファイルは、一方が黙って他方を置き換えるのではなく、番号が付きます。

      よくある質問

      SVG はどこかにアップロードされますか？

      されません。ファイルはあなた自身のブラウザがあなた自身のハードウェア上で読み、あなたが見ているほかのすべての画像を描くのと同じエンジンがキャンバスに描き、そのままダウンロードとして返します。このツールにはネットワーク機能が一切なく — 何も取りに行かず、何も送りません — ページの Content-Security-Policy は接続してよいアドレスをすべて挙げていますが、そのどれも当サイトのものではありません。

      SVG はどの大きさで書き出すべきですか？

      それを読む相手が求める値に、表示される画面のデバイスピクセル比を掛けたものです。CSS で200ピクセルを占めるロゴなら、Retina のノートPCには400、最近のスマホには600が必要で、それがここでいう @2x と @3x です。アプリのアイコンやストアの掲載画像なら、ストアが正確な数値を指定しており、それがその数値です。何も指定されていない場合は、長辺1024が便利な初期値です。たいていの用途に十分大きく、メールで送れる程度には小さいからです。

      大きくすると画質は落ちますか？

      落ちません。そしてここは、その答えが正直に「落ちません」になる唯一の場所です。ベクターはピクセルではなく指示なので、ブラウザは求められた大きさで曲線を描き直します。24ピクセルのアイコンから作った4000ピクセルは、24のときとまったく同じだけ鮮明です。できないのは逆向きです。いったん PNG になればほかと同じくピクセルなので、あとから結果をリサイズするのではなく、必要な大きさで書き出してください。

      SVG に width も height もありません。どの大きさになりますか？

      viewBox があれば、それです — その幅と高さはピクセルではなくユーザー単位ですが、ファイルの中にある唯一の数値であり、ブラウザはそれを図の自然な大きさとして扱います。viewBox もない場合は、行の横に 仮定 と表示し、300 × 150 を使います。 <img> が描いたであろう大きさです。いずれの場合も、ほしい大きさを指定すれば、その大きさで描かれます。

      PNG にすると文字の見た目が変わるのはなぜですか？

      フォントが SVG の中にないからです。文字を描く SVG はフォント名を指定し、探すのは端末に任せます。@import で Google Fonts から取ってくるファイルは、ここでは何も得られません。<img> を通して描かれる SVG は何も取りに行くことを許されないからです。これは、そのファイルがあなたの情報を外部へ送ることを止めているのと同じ規則です。直し方はどのデザイナーもすでに知っているもので — 書き出す前に、作図ソフトで文字をパスに変換することです。そうすれば図形になり、どこでも同じに見えます。

      複数のファイルを一度に変換できますか？

      できます。リスト上のどの SVG も同じ設定で描かれ、まとめて1つの zip で届きます。まとめて処理する場合は、たいてい倍率 —「ファイルが求めるサイズの4倍」— が正しい設定です。すべてを同じピクセル数に押し込めるのではなく、それぞれが自分のサイズから拡大されるからです。行をクリックすれば、その1つをプレビューに出せます。

      サイズの上限はありますか？

      私たちのではなく、ブラウザの上限があります。キャンバスは一辺16,384ピクセルを少し超えたあたりで音を上げ、iPhone や iPad の Safari は面積およそ1670万ピクセル — 4096 × 4096 — で止まります。それを超えると、真っ白な画像を返すのではなく警告します。ブラウザは行き詰まると toBlob が何も返さず、しかも説明するエラーも出さないからです。 1億ピクセルを超えると、このツールは拒みます。1バイトも書き出さないうちに、キャンバスだけで400 MB になるからです。

      透過はどうなりますか？

      PNG と WebP では保たれます。JPEG にはアルファチャンネルがまったくないので、頼んでも頼まなくても画像全体の後ろに色が塗られます — それがなければ透過部分がすべて黒くなり、JPEG の仕様ではなく不具合のように見えるからです。 PNG で背景色を指定するのも、まったくふつうの要望です。図をその色に合成して、穴を残さないようにします。

      スクリプトや外部画像を含む SVG も読めますか？

      読めますし、ブラウザが描く気のある部分だけを正確に描きます。 <img> から読み込まれた SVG は secure static mode にあります。スクリプトは走らず、外部参照は取得されず、アニメーションも再生されません — 得られるのは最初のフレームです。ですから外部の <image> を含むファイルは、その部分が欠けた状態で出てきます。それはブラウザがあなたに代わって拒んでいるということであり、このページが見たこともないファイルを安全に開ける理由です。

      画像リサイズツールとは何が違いますか？

      出発点です。画像リサイズツールはピクセルから始まるので — JPEG や PNG です — 大きくするには、そもそもなかった細部を発明しなければなりません。こちらは図から始まるので、発明するものがなく、気にすべき上限もありません。手元にあるのが SVG ならこちらが鮮明な結果をくれますし、写真ならあちらです。

      無料ですか。アカウントは必要ですか？

      無料です。アカウントも、ログインも、試用期間も、透かしもありません。ファイルの数にもサイズにも制限はありません。その費用を払うサーバーが存在しないからです — 処理はあなた自身の端末で起きています。このサイトには広告があり、それが費用を賄っています。広告にあなたのファイルに関する情報が渡されることはありません。

      オフラインでも動きますか？

      動きます。ページを一度読み込んでから通信を切っても、そのまま使えます。これは、何もアップロードされていないことを示すいちばん簡単な方法でもあります。描画のために図版をどこかへ送っている道具なら、線を抜いた瞬間に止まるからです。

      詳しい解説

      SVG を適切な大きさの PNG に変換する方法 ベクターには固有のピクセルサイズがないので、数値はあなたが決めます。画面、アプリのアイコン、印刷機のそれぞれでその数値がどこから来るのか、そして図がピクセルになるとき何が変わるのか。
