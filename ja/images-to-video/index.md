# 画像→動画変換ツール

レンダリング連番、タイムラプス写真、スライドショーからMP4を作ります。

> 連番画像をブラウザーでMP4に変換します。レンダリングやタイムラプスには画像1枚につき1フレーム、スライドショーには写真1枚につき数秒を指定します。アップロードもアカウントも不要です。

これはhttps://abox.tools/ja/images-to-video/にあるブラウザー用の対話型ツールです。ファイルはそのブラウザーを実行する端末上で処理します。意図した共有や任意の通信機能はページ内で説明します。以下は文章による説明です。利用するにはアドレスを開いてください。

## 画像は**ブラウザー内で処理**されます。処理のためのアップロードはありません。

すべてのフレームをエンコードするのはお使いのブラウザで、動画を組み立てるのはこの端末のメモリの上です。エンコーダーがネットワークに触れることはなく、仮に触れたとしても、このページの向こう側に画像を受け取るサーバーが存在しません。

- ✗ アップロードなし
- ✗ 登録なし
- ✓ オフラインで動作
- ✓ ソース公開
- ✓ ファイルは端末に残ります

## 連番画像やスライドショーをMP4に変換する方法

1. **画像を選びます。** フォルダごと選択欄にドロップするか、ファイルを手で選んでください。ブラウザがディスクから直接読み出します。その間に何かがどこかへ送られることはありません。
2. **連番ならフレーム、スライドショーなら秒を選びます。** 番号付きのレンダリング画像には「名前順に並べる」を使い、最初と最後のタイルを確認します。レンダリング連番や写真のタイムラプスは画像1枚につき1フレームのままにし、フレームレートを素材に合わせます。スライドショーでは秒に切り替え、3などの表示時間を入力して「全部に適用」を押します。ドラッグで並べ替えられ、画像ごとに表示時間を変えることもできます。
3. **解像度とフレームレートを選びます。** 最初の書き出しには1080pを選ぶか、出力先に合わせて正方形や縦長を使います。「いちばん大きい画像に合わせる」は、画像全体で最大の幅と最大の高さを取ります。「内側に収める」は画像全体を残し、「画面いっぱいに」は端を切ります。エンコードの前に長さと出力サイズの概要を確認してください。
4. **動画を作ってダウンロードします。** エンコードは手元のハードウェアで動くので、かかる時間は順番待ちではなく端末の性能次第です。できあがったMP4は、そのままブラウザのダウンロードへ渡します。

## よくある質問

### 画像はどこかにアップロードされますか？

されません。画像の読み込みも合成もエンコードも、お使いのブラウザが手元のハードウェア上で行います。このツールにサーバー側は存在しません。ページの`Content-Security-Policy`には接続してよいアドレスがすべて挙がっていますが、そのどれも当サイトのものではありません。唯一の例外は任意機能の「ウェブアドレスから追加」で、貼り付けた画像を取得しに行くため、そのサーバーにはこちらのIPアドレスが見えます。

### どの画像形式が使えますか？

ブラウザがデコードできる静止画形式ならどれでもです。実際にはJPG、PNG、WebP、GIF、AVIF、そしてAppleの端末ではHEICです。ここに別途の対応表を作って保守する必要はありません。デコードは当サイトではなく、ブラウザの仕事だからです。

### どの動画形式で書き出されますか？

推奨の出力はH.264映像のMP4です。代替手段はリアルタイムで録画し、通常はWebMになりますが、WebMに対応する編集ソフトは少なめです。代替の録画中はタブを表示したままにしてください。タイミングはおおよそで、デコードが遅れると画像が飛ばされることがあります。番号付きの連番を正確に出力するには、ブラウザーが対応していればMP4エンコーダーを使ってください。

### BlenderやAfter Effectsのレンダリング連番に使えますか？

使えます。番号付きのレンダリング連番こそ、これが想定している用途です。レンダラーが書き出したフレームを追加し、表示時間を1フレームのままにして、フレームレートをレンダリングに合わせてください。「名前順に並べる」は期待どおりの数え方をするので、`frame_2`は`frame_10`より後ではなく前に来ます。\
\
始める前に知っておく価値のあることがひとつあります。H.264にはアルファチャンネルがないので、透過は引き継がれず、背景色に合成されて平らになります。アルファを保ちたい場合は、お使いの編集ソフトでフレームを合成してください。

### 写真からタイムラプスを作れますか？

作れますし、レンダリング連番と同じ仕事です。各写真を1フレームだけ映すようにして、フレームレートを選んでください。30fpsなら写真30枚が動画1秒に、12fpsなら同じ写真が2.5秒になります。\
\
「日付順に並べる」はファイルの更新日時を使います。更新日時は写真をコピーしたり編集したりすると変わることがあります。ファイル名が0001からやり直しになっている場合は順序を確認してください。大きさの違う写真が混ざっていても問題はありません。「いちばん大きい画像に合わせる」は最大の幅と最大の高さから始め、長辺を7680ピクセルまでに制限して偶数の寸法に丸めます。出力サイズの概要を確認してください。非常に大きな元画像は縮小されることがあります。

### 画像の枚数や動画の長さに制限はありますか？

画像の枚数に固定の上限はありませんが、MP4の書き出しは4 GiB（約4.3 GB）未満に収める必要があります。完成した動画はダウンロードの前にメモリ上で組み立てられるため、その上限よりかなり前に端末のメモリが足りなくなることがあります。ブラウザーのエンコーダーも出力の寸法を制限します。大きな書き出しが失敗したら、解像度を下げるか、連番を短くするか、分割してください。

### 無料ですか。アカウントは必要ですか？

無料です。アカウントも、ログインも、試用期間もありません。このサイトには広告があり、それが費用を賄っています。広告に画像の情報が渡されることはありません。

### オフラインでも動きますか？

動きます。ページを一度読み込んでから通信を切っても、そのまま使えます。何もアップロードされていないことを示す、いちばん簡単な方法でもあります。処理のために画像をどこかへ送っている道具なら、線を抜いた瞬間に止まるからです。

### 音楽やBGMを付けられますか？

まだできません。このツールが作るのは映像だけで、書き出すMP4には映像トラックが1本あるだけで、音声トラックはありません。必要な場合は、あとから動画編集ソフトで音を足してください。

## この主張を確かめる方法

- **処理はこのブラウザー内で行います。** 入力と結果はブラウザー内で処理し、処理コードはそれらを処理用にアップロードしません。Content-Security-Policyは資源と接続先を制限しますが、許可済みの相手はリクエストを受け取れます。内容は検査せず、何も送られないことを単独で証明しません。具体的な操作の要求とソースを比較するか、切断中にローカル操作を完了してください。
- **エンコードは手元で行います。** WebCodecsが動くのはブラウザの中で、できあがったファイルはそのままダウンロードへ渡ります。このアプリにサーバー側は存在しません。
- **Googleが読み込むものと、渡されないもの。** 広告と計測のスクリプトはGoogleから来ています。そのどちらにも、画像に関する情報は渡されません。ファイルも、サムネイルも、名前も、サイズも、枚数もです。画像を読み、デコードし、合成し、エンコードするコードはすべてこのオリジンから配信され、リポジトリに載っています。
- **寄付ボタンは何も読み込まず、何も渡されません。** ヘッダーの「Buy me a coffee」ボタンは、このページ自身が描いており、どこからも何も読み込みません。これはリンク以上のものではありません。訪問を報告しませんし、閲覧者や画像に関する情報も渡されません。押さない限り何も起きませんし、押した先は他人のサイトです。
- **意図した例外がひとつあります。** 「ウェブアドレスから追加」を使うと、画像を取得するためにそのサーバーへ接続するので、相手にはこちらのIPアドレスが見えます。取りに行くのは貼り付けた画像だけで、向きは内側だけです。開いているのは`img-src`であって、`connect-src`ではありません。下のカウンターは、接続した外部オリジンをすべて列挙します。
- **オフラインで動きます。** 通信を切っても、ウェブアドレスからの読み込み以外はすべてそのまま動きます。これがいちばん単純な証明です。

**自分で確かめてください。**以上のどれも、鵜呑みにする必要はありません。このページは、リポジトリにあるテンプレートと設定から、誰でも読んで実行できるビルドスクリプトが生成しています。その結果は`dist`ブランチに置いてあるので、配信されているものと、ソースをビルドした結果とを差分で比べられます。 https://github.com/A-Box-of-Tools/website
