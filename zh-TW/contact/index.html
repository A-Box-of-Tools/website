讀信的是一個人，而且每封都讀。下面寫的是這兩條路各自適合什麼、一份缺陷報告要寫上什麼才真能被找出來，以及你發出去之後會發生什麼。

最後更新 2026年8月27日

兩條路

郵件，hi@abox.tools。直接寄到寫這些工具的人手裡。凡是你不太想擺到明面上說的事，走這條路：一樁隱私上的顧慮，一項版權或商標方面的主張，一個安全問題，或者一個非得附上別人不該看的檔案才說得清的缺陷。

問題追蹤頁，github.com/A-Box-of-Tools/website/issues。看的是同一個人。凡是別人也能跟著受益的事，走這條路：某個工具處理不好某一類檔案，某句譯文在你的語言裡讀著不對，一個功能建議，或者一個答案該留在下一個人找得到的地方的問題。這條路要有 GitHub 帳號，郵件不用。

沒有電話，也沒有線上客服。這是一個人的專案，擺一條沒人坐守的熱線，比直說更糟。

你寫完之後會發生什麼

有人會讀，通常在幾天之內。回信用英文。

一個能復現的缺陷，通常一兩週內修好，修復會出現在公開的提交記錄裡；要是你是以 issue 的形式提的，你的報告也會掛在旁邊。功能建議會得到一個誠實的答覆，有時候這個答覆是不行。ROADMAP.md 給每一個被否掉的想法都留了一段，寫明為什麼，所以這裡的「不行」是帶著理由來的。

不會發生的事：你不會被加進任何郵件列表，你的地址也不會給任何人。它只用來回你的信，別的都不用。

怎麼把缺陷說清楚，好讓人找得到

這些工具跑在你的機器上，不在伺服器上，所以這邊沒有日誌可查。發生過的一切都發生在只有你能看見的地方。因此一份寫明瞭是哪個頁面、哪裡不對的報告，在這裡比在幾乎任何別處都值錢。有用的細節是這些。

  • 哪個工具，把地址帶上。一共三十六個，其中好幾個做的事兒捱得很近。
  • 瀏覽器和版本，以及是不是手機。這類缺陷裡有相當一部分，其實是某個瀏覽器對影片容器或者影像編碼器的理解，而不是工具本身的毛病。
  • 那個檔案是什麼：格式，大概多大，從哪來的，比如是哪臺相機或者哪款手機。檔案本身不用發過來。要是剛好有一個不涉及隱私、又能復現問題的小樣本，那幫助極大；沒有的話，描述一下通常也夠了。
  • 你以為會得到什麼，實際得到了什麼。「沒反應」和「匯出的片子沒有聲音」是兩個缺陷，原因也不一樣。
  • 瀏覽器控制檯裡飄紅的東西，前提是你知道怎麼開啟它。把第一條錯誤複製過來，比把滿屏截下來更有用。

安全和隱私方面的報告

這類事情走郵件，別公開發：hi@abox.tools。凡是能讓這裡的頁面碰到它本不該碰的檔案、把檔案送到什麼地方去、或者執行沒有下發給它的程式碼的問題，都會被認真對待，並在同一周內看。隱私頁說不收集、而網站實際上收集了的任何情況，也一樣。

沒有漏洞賞金計畫，也沒有錢。這話與其讓人做完活才發現，不如先說明白。提交記錄和版本說明裡的署名可以給，你不要也一樣痛快。

版權、商標和下架請求

本站沒有使用者上傳的內容，這裡也沒有任何地方可供誰釋出東西：工具是在訪客自己的瀏覽器裡處理檔案的，訪客開啟的和做出來的，都到不了本站。所以沒有託管的內容可以下架，也沒有帳號可以封停。

但如果本站自己寫的、畫的東西，一個頁面、一張插圖、一段程式碼，侵犯了你的權利，請寫信到 hi@abox.tools，附上那個頁面的地址和具體是哪一處，會直接處理。

廣告與商務來信

本站透過 Google 展示廣告，合作就到此為止。直接投放、軟文、付費連結、投稿和交換連結，一律謝絕，原因不是清高：一個悄悄替別人帶話的頁面，讀者已經沒法掂量它說的話了，而本站的每一句話都是請讀者去核實的。這封郵件就省了吧。

把這些工具用在生意上不需要許可，也不需要授權：任何用途都可以隨便用，包括在公司裡用。複用程式碼則按儲存庫裡的許可證來，那份許可證很寬鬆，把某個模組整塊搬走，正是它存在的意義。

你在寫給誰

abox.tools 是一個獨立、自負盈虧的專案，由一個人在加拿大安大略省經營。它不是公司，上面那個地址背後也沒有客服部門。回信比公司慢，原因在這裡；回信是由讀過程式碼的人親手寫的，原因也在這裡。關於頁寫了這東西是誰做的、工具為什麼是這個樣子，以及網站的開銷從哪來。
