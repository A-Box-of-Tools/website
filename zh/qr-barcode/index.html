● 你的二维码和其中的文字不会被上传。这里根本没有服务器。

二维码说白了就是对一串字符做算术，没有文件要发，也没有服务要问。挑模式、选版本、里德-所罗门纠错、掩码、条形码的条纹和它下面的校验位，每一步都发生在这个页面里大约一千行你读得懂的 JavaScript 中。这个工具没有任何形式的网络功能，而这一点在这个页面上比在大多数页面上都更要紧，因为被编码的东西常常是一个 Wi-Fi 密码。

隐私这一条要怎么验证

  • 你打进去的东西无处可去。Content-Security-Policy 把这个页面允许联系的地址全列了出来，其中没有一个属于本站。这里没有能收 Wi-Fi 密码的接口，代码里也没有一行会去发送它，就算真有那么个接口也一样。
  • 这里没有任何东西会去联网取数据。src/ 里找不到 fetch，找不到XMLHttpRequest，也找不到 sendBeacon。码是靠算术从那串字符构造出来、再画成 SVG 的，就在这个页面里，在你的机器上。
  • 这个码不指向我们。你打进去什么，码里就装什么。好几个免费生成器给你的码里装的是一个指向他们自己网站的链接，再由那边跳转到你那儿，于是每一次扫描都被他们数了一遍，而且他们哪天不再为那个域名付钱、或者认定免费额度到期了，这个码就作废了。这里不做短链，不跳转，不追踪，页面上显示的那串字符，就是图里的那串字符。
  • PNG 是从屏幕上那个 SVG 做出来的。下载的东西不是另跑一次、可能跟预览对不上的渲染。同一份标记交给浏览器，画到一张画布上，这也是它不联系任何东西就能做成的原因，里面既没有字体要取，也没有图片要加载。
  • Google 加载了什么，又拿不到什么。广告脚本和统计脚本来自 Google，捐助按钮来自 Buy Me a Coffee。你打进去的东西，一个字符也没有交给它们。把字符串变成码的每一行代码都由这个源提供，也都摆在仓库里。
  • 断网也照样能用。断开网络，这个工具跟原来一模一样，因为它里面从来就没有联网这一步。这是最省事的一条证明。

你可以自己核对。上面这些都不用你凭信任接受。这个页面是 仓库里的模板和配置，经过一个你能读、也能自己跑的构建脚本生成出来的， 结果提交在 dist 分支上，所以你可以拿实际提供的内容和从源码 构建出来的结果直接对比：

怎么在什么都不上传的情况下生成二维码
 
     
  1.  挑一种码。二维码什么都能装，也是手机摄像头会去找的那一种，所以没人另有交代的话，答案就是它。条形码装的是一个数字，你需要哪一种由将来扫它的那个人决定，商店要 EAN-13 或 UPC-A，运输纸箱要 ITF-14，内部用途通常是 Code 128。 
    2.  
  2.  说明里面装什么。链接是最常见的情形，而它上面那几个框会拼出手机认得的其他格式：一个会主动提示加入的 Wi-Fi 网络、一张会主动提示保存的联系人名片、一个邮件地址、一条短信、一个电话号码、地图上的一个地点。不管你挑哪个，拼好的那串字符都会显示在页面上，二维码里装的从来就只有它。 
    3.  
  3.  决定它能扛多少损伤。四个等级放进去的纠错数据有多有少，而纠错越多，码就越大越密。屏幕上用 L 就够，普通纸张用 M，会被摸来摸去、印得很小、或者贴在晒得到太阳的玻璃上的用 H。菜单上那种每天要擦一遍的码，值得上 Q 或者 H。 
    4.  
  4.  设好尺寸、留白和颜色。留白是码的一部分，规范要求四周各留四个模块的静区，而把它裁掉，是印出来的码扫不出来最常见的单一原因。深色在浅色上，而且要有真实的对比，扫描器读的是两者之间的差，所以白底浅灰不行，浅色在深底上则会在相当多的读取设备上直接失败。 
    5.  
  5.  用你手上那台手机试一下。在印一千份之前，先扫一下屏幕上这一个。这要十秒钟，却能抓住预览抓不到的一整类错误：Wi-Fi 密码里有个字符本该转义、链接漏了https://、条形码数字少了一位。 
    6.  
  6.  把 SVG 拿走。它是以指令而不是以像素表达的码，所以印成任何尺寸都不发虚，而发虚的边缘正是扫描器分辨不了的东西。你要粘进去的地方不收 SVG，那就把 PNG 也拿走，它是按每个模块整数个像素画的，边缘同样不糊。 
    7.  
 
常见问题
 
 
 我打进去的东西会被发到什么地方去吗？ 
 不会。二维码就是对一串字符做算术，而这套算术在你自己的机器上、你自己的浏览器里跑。这个工具没有任何形式的网络功能，从不取什么，也从不发什么，而页面的 Content-Security-Policy 把它可能联系的地址全列了出来，其中没有一个属于本站。这一点在这个页面上比在大多数页面上都更值钱，因为人们最常放进二维码里的东西，是自家 Wi-Fi 的密码。 
 
 
 这些码会过期，或者过一阵子就不能用了吗？ 
 不会，它们也做不到过期。你打进去什么，码里就装什么，所以扫它永远原样还给你那串字符。会过期的是那些里面装着别人地址的码，一个“动态”二维码装的是一个指向生成方服务器的链接，再由那边跳转到你那儿，这就意味着他们可以数每一次扫描、可以改它跳去哪儿，也可以在试用期结束时把它关掉。这里没有任何东西经过跳转。 
 
 
 它免费吗，能商用吗？ 
 免费，没有账号，没有水印，生成多少个也没有限制，结果可以放到产品、海报或者店面上。QR Code 是电装波动（Denso Wave）的注册商标，而他们已经声明不会对使用这些码的人主张这项权利，规范以 ISO/IEC 18004 发布，可以自由实现，这个页面做的就是这件事。本站带广告，经费就是从那儿来的。 
 
 
 我该选哪个纠错等级？ 
 没有特别理由就选 M。L 生成的码最小，屏幕上完全够用；M 扛得住普通的翻来翻去；Q 和 H 是给那些会被印得很小、覆膜、贴在玻璃上，或者被 logo 挡掉一部分的码用的。每往上一级都要多放一些校验数据，同样多的文字就需要一个更大的图形，从 L 换到 H，同一串字符的模块数大约会翻倍。 
 
 
 一个二维码能装多少？ 
 在最大的尺寸、177 个模块见方时，最多 7,089 位数字、4,296 个大写字母和数字，或者 2,953 字节的其他内容，而这还是在最弱的纠错下，最强纠错下大约只有这些的三分之一。实际上，限制不在格式而在扫描器，超过几百个字符之后，模块小到普通手机摄像头在一臂距离外就分辨不出来了。码长得离谱，通常说明该往里面放的是一个短链接。 
 
 
 为什么我把链接写成小写，码就变大了？ 
 因为二维码有一个专给大写字母和数字用的模式，两个字符只占十一位，而小写没有这样的模式，每个要占八位。一个写成HTTPS://EXAMPLE.COM/PAGE 的网址，可以比同一个小写网址小三分之一。协议名和主机名不区分大小写，把它们喊出来除了尺寸什么都不改；主机名后面的路径是区分的，那部分别动。 
 
 
 它除了生成，还能读二维码吗？ 
 暂时不能。读一个码意味着解一张图，在照片里找出那个图形、校正拍摄的角度、把损伤修回来，这和画一个码是两件事，而且要大得多。它可以按和这里其他一切相同的条件建起来，它也在清单上。眼下你手机的摄像头本来就能做，而且做得很好。 
 
 
 留白是干什么用的，能不能小一点？ 
 二维码周围那圈空白是码的一部分。读取器靠它判断图形在哪儿结束，规范要求四边各留四个模块，条形码要十个左右。你在这里可以把它设成零，画面显得更齐整，然后相当多的扫描器会干脆看不见它，花哨的背景上尤其如此。地方不够的话，正确做法是把码做小，而不是把它的留白裁掉。 
 
 
 我需要哪种条形码？ 
 扫它的那个人要哪种就是哪种。EAN-13 是北美以外的零售条形码，UPC-A 是北美那个，两者都需要一个由 GS1 发给你的号码，因为那个号码标识的是你的公司，不只是这件商品。EAN-8 是给小包装用的短版本。ITF-14 印在运输纸箱上。Code 128 和 Code 39 除了数字还能装文本，而且完全不用注册，这让它们成为一切内部用途的正确答案，资产、货架、工单都算。 
 
 
 校验位是什么，工具为什么给我加了一位？ 
 它是零售条形码的最后一位，由它前面那些数字算出来，好让扫描器能区分“读错了”和“读到了”。EAN-13 要十二位数字，第十三位由它算；UPC-A 要十一位，第十二位由它算。你输短的那个号，这个页面把它补上。你输完整的号，它会核对你给的那一位，而且是拒绝，不是悄悄改掉，因为一位被悄悄改对的数字，意味着一张扫出来是别人商品的标签。 
 
 
 我能在二维码中间放一个 logo 吗？ 
 这里不能，但别处能行的道理值得知道，靠的是纠错。在 H 级下，大约 30% 的模块被毁掉，码依然读得出来，所以一个盖住比这少一些、又正好落在中间那块没有定位图形的地方的 logo，属于可修复的损伤。用 H 级生成，拿进你的图像编辑软件，把 logo 控制在面积的五分之一以内，然后用一台真手机测一下，别光凭信任。 
 
 
 为什么 SVG 比 PNG 好？ 
 因为码就是一堆边缘，而 PNG 只有固定数量的像素来拼出这些边缘。把它放大，每条边都会发虚，而发虚的边缘正是扫描器最头疼的东西。一台 1200 dpi 的打印机拿到一张 512 像素的 PNG，等于被要求去凭空编出那些差别。SVG 是以指令表达的那些方块，所以印在名片上和印在广告牌上一样锐利。这里的 PNG 按每个模块整数个像素画，那是 PNG 能做到的最好情况。 
 
 
 断网能用吗？ 
 能。页面加载一次之后断开网络，它照样干活。这也是证明“什么都没上传”最省事的办法，真要把你的文字送出去画码，拔线那一刻就停了。
