栅格化用的就是刚刚把它画到你屏幕上的那个引擎。你的文件从硬盘上读进来，根标签由 src/svg.js 里一百行你读得懂的代码改写成你要的尺寸，然后画到一张你浏览器本来就带的画布上。这个工具没有任何形式的网络功能，没有什么可取，也没有什么可发，何况这个页面的另一端根本就没有服务器，想送 logo 也没地方送。

隐私这一条要怎么验证

  • 你的图稿无处可去。Content-Security-Policy 把这个页面允许联系的地址全列了出来，其中没有一个属于本站。这里没有能收你文件的接口，代码里也没有一行会去发送文件，就算真有那么个接口也一样。
  • 这里没有任何东西会去联网取数据。src/ 里找不到 fetch，找不到XMLHttpRequest，也找不到 sendBeacon。整个栅格化器就是一个装着你自己文件 blob 的 <img>、一次往画布上的 drawImage，和一次 canvas.toBlob。
  • SVG 是一份文档，而这里用的是它动不了手的那种模式。一个 SVG 里可以带 <script>、一个远程的<image href="https://…">、一份样式表和一个网络字体。透过 <img> 绘制时，它处在规范所说的安全静态模式，脚本不运行，那些地址一个都不会被请求。这是浏览器给的保证，不是我们给的承诺，也正因如此，这个页面才敢打开一个从没见过的文件，而那个文件没法往家里打电话。
  • Google 加载了什么，又拿不到什么。广告脚本和统计脚本来自 Google，捐助按钮来自 Buy Me a Coffee。关于你图稿的信息，一条也没有交给它们。读取、定尺寸、绘制文件的每一行代码都由这个源提供，也都摆在仓库里。
  • 断网也照样能用。断开网络，这个工具跟原来一模一样，因为它里面从来就没有联网这一步。这是最省事的一条证明。

你可以自己核对。上面这些都不用你凭信任接受。这个页面是 仓库里的模板和配置，经过一个你能读、也能自己跑的构建脚本生成出来的， 结果提交在 dist 分支上，所以你可以拿实际提供的内容和从源码 构建出来的结果直接对比：

1 选择 SVG 文件

    2 说明它该有多大

    这是矢量图唯一没法替你回答的问题。SVG 里没有像素，里面装的是绘制的指令，你说多大它就按多大画。下面这个数字也不是一堵你在往上顶的墙，不像处理照片那样，从一个 24 像素的图标出发画到 4000 像素，跟 24 像素时一样锐利。

    列表上每个文件都从它自己的尺寸乘上去，所以一批画在不同尺寸上的图标，彼此之间的比例不会乱。

    高度跟着这幅图的形状走。

    宽度跟着这幅图的形状走。

    哪条边更长，哪条边就变成这个数，另一条跟着走，所以一个宽 logo 和一个高 logo，长边尺寸是一样的。

    3 挑格式

    只对 JPEG 和 WebP 起作用，PNG 没有质量旋钮可拧，因为它是无损的。纯色块和硬边缘，也就是 SVG 的大部分内容，恰恰是有损编码器最不擅长的东西，所以这里的默认值比处理照片时更高。

    4 看一眼，然后保存

    预览是由写文件的同一套代码、从你选的那个文件、在这台机器上画出来的。值得检查的是一幅图变成像素时会变的那两件事，一条本来只有半个像素宽、现在变灰了的发丝线，还有文字，它用的是这台机器上有的字体，不是从网上取来的那一个。

    加一个 SVG，它就会出现在这里。

    完成

      怎么在不上传的情况下把 SVG 转成 PNG

      1. 选那个 SVG。拖一个到下面的方框里，或者挑一整个文件夹一次转完。浏览器直接从你的硬盘上读，整个过程没有东西被送去别处。每一行都会说明这个文件认为自己有多大，而且尺寸来自它的 viewBox、还是因为文件根本没声明而只能假定，说法是不一样的。
      2. 说明要多大。给文件自身尺寸的一个倍数，是最快的答案，处理一整批时也是对的那个，每张图都从它自己的起点缩放，一套图标之间的比例不会乱。要不然就说一个宽度、一个高度、最长边，或者一个两边都给定的框。这里填一个很大的数字不像处理照片那样要付代价，图是按那个尺寸重新画的，不是被拉上去的。
      3. 需要的话，加上高 DPI 副本。手机和 Retina 笔记本每个 CSS 像素要画两到三个设备像素，所以一个 200 像素的 logo，背后需要一个 400 或者 600 像素的文件。勾上 @2x 和@3x，它们出来时的命名正是 Xcode、Android 工具链和 CSS image-set() 都认的那种，而且每一个都正好是第一个的两倍或者三倍，不是各自单独取整。
      4. 挑格式，再定透明怎么办。没有特别理由就选 PNG，它无损，保留透明，纯色块在里面还压得很好。JPEG 根本没有透明，所以不管你挑不挑，都会有一个背景色被画进去，没有它，每一个透明像素都会变成黑的。WebP 两样都行，文件还更小，代价是老到读不了它的软件。
      5. 下载之前看一眼预览。它是由写文件的同一套代码、从你的文件、在你的机器上画出来的。一幅图变成像素时有两件事会变，这里都看得见，一条本来只有半个像素宽的发丝线会变灰，任何文字都会用这台电脑上有的字体来画，而不是从网上取来的那一个。
      6. 把文件拿走。一个文件一次下载，或者整批打成一个 zip。名字跟着它们来源的那个 SVG，副本上带 @2x 和 @3x，而两个本来会重名的文件会被加上编号，不会让其中一个悄悄把另一个盖掉。

      常见问题

      我的 SVG 会被传到什么地方去吗？

      不会。文件由你自己的浏览器在你自己的硬件上读取，由渲染你看到的其他每一张图片的同一个引擎画到画布上，然后作为下载还给你。这个工具没有任何形式的网络功能，从不取什么，也从不发什么，而页面的Content-Security-Policy 把它可能联系的地址全列了出来，其中没有一个属于本站。

      我该按多大的尺寸栅格化一个 SVG？

      读它的那个东西要多大就多大，再乘以它将要出现的那块屏幕的设备像素比。一个占 200 CSS 像素的 logo，Retina 笔记本需要 400，近几年的手机需要 600，这里 @2x 和 @3x 副本就是这么来的。应用图标或者商店素材，商店会给出一个确切的数字，那个数字就是答案。什么都没人告诉你的时候，最长边 1024 是个好用的默认值，大到几乎什么用途都够，小到还能用邮件发。

      放大会损失质量吗？

      不会，而且这是少有的、这个答案可以老老实实说“不会”的地方。矢量图是指令而不是像素，浏览器会按要求的尺寸把那些曲线重新画一遍，从一个 24 像素的图标出发画到 4000 像素，跟 24 像素时一样锐利。做不到的是反过来走，一旦它成了 PNG，它就和别的东西一样是像素了，所以请按你需要的尺寸栅格化，别事后再去缩放结果。

      我的 SVG 没有 width 和 height，我会得到多大的图？

      有 viewBox 的话，就是它里面的尺寸。它的宽高是用户单位而不是像素，但那是文件里仅有的数字，浏览器会把它们当作这幅图的自然尺寸。连 viewBox 也没有，页面会在那一行旁边写假定，并使用 300 × 150，那也正是一个 <img> 会用的尺寸。不管哪种情况，你都可以直接说出你要的尺寸，图就按那个画。

      为什么 PNG 里的文字看起来不一样？

      因为字体不在 SVG 里。一个画文字的 SVG 只是写下一个字体名字，剩下的交给这台机器去找，而一个用 @import 从 Google Fonts 拉字体的文件，在这里什么也拿不到，透过 <img> 绘制的 SVG 不被允许请求任何东西，而这正是让它没法带着你的文件往家里打电话的同一条规则。解法是每个设计师都已经知道的那个，导出之前先在绘图软件里把文字转成路径，那样它就是几何图形，在哪儿看都一样。

      它能一次转好几个文件吗？

      能。列表上每一个 SVG 都用同一套设置渲染，这一批打成一个 zip 下来。处理一整批时，用倍数通常是对的设置，比如“文件自己要求尺寸的 4×”，因为每张图都从它自己的尺寸缩放，而不是被一律逼到同一个像素数。点任意一行，就能把那一个放进预览。

      有尺寸上限吗？

      有浏览器的，没有我们的。画布在一条边超过 16,384 像素之后的某处就撑不住了，而 iPhone 和 iPad 上的 Safari 在大约 1670 万像素的面积上就停了，也就是 4096 × 4096。超过这个数，页面会提醒你，而不是还给你一张空白图，后者才是浏览器撑不住时的表现，toBlob干脆什么都不返回，也不给一句错误来解释自己。超过一亿像素，工具会直接拒绝，因为那意味着还没编码一个字节，画布就已经占了 400 MB。

      透明会怎么样？

      在 PNG 和 WebP 里会保留。JPEG 根本没有 alpha 通道，所以不管你要不要，整张图后面都会被刷上一个颜色，没有它，所有透明的地方都会变成黑的，那看起来像个 bug，而不像 JPEG 的正常行为。用 PNG 时也挑一个背景色，同样是完全正常的需求，它把图压平到那个颜色上，而不是留一个洞。

      它能读一个里面带脚本或者外部图片的 SVG 吗？

      能读，而且它会精确地画出浏览器愿意画的那些部分。透过<img> 加载的 SVG 处在安全静态模式，脚本不运行，外部引用不被请求，动画也不播放，你拿到的是第一帧。所以一个里面有远程 <image> 的文件，出来时那一块是缺的。那是浏览器替你拒绝了，也正因如此，这个页面才敢放心打开一个从没见过的文件。

      这个和图片缩放有什么区别？

      区别在源头是什么。图片缩放从像素出发，一个 JPEG、一个 PNG，所以放大就不得不编造本来不存在的细节。这一个从一幅图出发，没有什么要编造，也没有值得担心的上限。你手上是 SVG，这一个能给你锐利的结果；你手上是照片，那就用那一个。

      它免费吗，需要注册吗？

      免费，没有账号，不用登录，没有试用期，也没有水印。文件的数量和大小同样没有上限，因为没有哪台服务器在为它们掏钱，活是在你自己的机器上干的。本站带广告，经费就是从那儿来的，广告拿不到任何关于你文件的信息。

      断网能用吗？

      能。页面加载一次之后断开网络，它照样干活。这也是证明“什么都没上传”最省事的办法，真要把你的图稿送出去渲染，拔线那一刻就停了。
