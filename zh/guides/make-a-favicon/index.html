怎么做一个在十六像素下还认得出来的 favicon

favicon 不是你 logo 的一张小图。它是一组固定尺寸的图片，装在一个大多数人从来没打开过的容器里，而其中最小的那张，才是所有人真正看到的那张。这里讲的是你需要哪些尺寸、旁边还要放哪些文件，以及你的 logo 撑不过这一路缩小时该怎么办。

打开图片转 ICO 进去一张图。出来浏览器、Windows 或 Mac 要的每一个尺寸。

最后更新 2026 年 8 月 20 日

短答案

打开图片转 ICO，拖进去一张至少 256 像素的方图，预设保持网站 favicon，然后下载 favicon.ico。把它放在你站点的根目录，让 https://yoursite.com/favicon.ico 能应答。不管你的 HTML 有没有提到它，每个浏览器都会去要这个地址，所以严格来说你不必再做别的。

下面全部内容，才是让一个图标从“技术上存在”变成“真的认得出来”的那部分：里面装哪些尺寸、iPhone 和 Android 另外要什么，以及你的 logo 撑不过十六像素时该怎么办。

为什么它是一组尺寸，而不是一张图片

一个 .ico 文件是一个容器。里面装着同一个东西在不同尺寸下的好几张完整画面，而读这个文件的那一方，会挑最接近它所需尺寸的那一张。

这听起来像冗余，但它不是。一个要把你的图标画成十六像素的浏览器有两个选择：读一张你自己画的十六像素版本，或者当场把一张更大的缩下去。第二种更差，而且差得看得见 — 一个细节丰富的 logo 被自动缩小，出来的是一团糊，而一张你亲眼看过的十六像素版本，是你有机会去简化的东西。这个格式装好几个尺寸的全部理由，就是给你这个机会。

对一个网站来说，三个尺寸是惯例，而每一个都有它的理由：

  • 16×16 — 浏览器标签页、地址栏、书签菜单。这是人们真正看到的那一个。如果你只能弄对一个，就弄对这一个。
  • 32×32 — 书签栏、指向你网站的 Windows 桌面快捷方式，以及高 DPI 屏幕上的大多数浏览器 —— 它们是从 32 画出标签页图标再缩下去的。
  • 48×48 — Google 读取站点图标用于搜索结果时用的尺寸，以及 Windows 的中等图标视图。

比这更大的，应该放在 .ico 旁边的 PNG 里，而不是塞进它里面，理由在下面讲手机文件的那一节。

十六像素问题

这是没人提醒你的那部分。十六像素在普通屏幕上大约是四毫米：总共 256 个点的一张网格，比这句话里的字母还少。几乎没有哪个为招牌、名片或者网站页头设计的东西，能撑过被缩到这个程度。

按顺序消失的东西：

  • 文字。一个文字标塞进方框里之后大约三个像素高。它不会变成小号文字，它会变成一根灰条。这就是为什么几乎每一家既有符号又有名字的公司，都单用那个符号做 favicon，而没有符号的那些则用单个字母。
  • 细线条。一个 512 像素 logo 上一个像素宽的边框，到了十六像素就是三十二分之一个像素。它会渲染成沿着边缘的一层淡灰雾，或者干脆消失。
  • 渐变和阴影。没有地方容纳一段过渡。一层柔和的投影会变成一圈脏边。
  • 细节里面的细节。一个“写着字的文档”图标会变成一个带污渍的矩形。

解法不是一个设置，而是另一幅图：一个只有一两个形状、高对比、除了单个字符没有任何文字的简化标记。有意识地在 32 或 48 像素下画那个版本，并把它当作源图。

一个工具能做的，是在你发布之前把问题摆给你看。图片转 ICO 里的预览会把每个尺寸按它在屏幕上的真实大小画出来，而那是判断这件事的唯一办法 — 一个十六像素的图标被放大到六十四像素显示，看着挺好，什么也说明不了。

你的 logo 不是方的。补白还是裁剪？

图标永远是方的，而大多数 logo 不是，所以总得发生点什么。有三个答案，而它们并不一样好。

补白会把整张图保住，在它上下留出空间。它是稳妥的默认值，也是宽文字标的错误选择：把一个宽是高三倍的东西装进方框里，它只占三分之一的高度，而在十六像素下，那是五个像素的 logo 加十一个像素的什么都没有。

裁到中间会从中心取出最大的那块正方形。对一个组合标 — 一个符号旁边带着公司名 — 来说，这往往从两者中间直接切过去。更好的做法是先自己把源图裁掉，只留下那个符号，再拿它去转换。

拉伸会把图片挤扁以贴合。几乎没有哪种情况下它是对的，而它之所以还被提供出来，主要是为了让工具不至于不吭声就这么干。

对一个宽 logo 的通用答案是：别转那个 logo。转它当中那个能单独立住的部分。

透明，还是一个实色背景？

对网站来说通常是透明。浏览器标签页是灰的、白的还是近黑的，取决于浏览器和主题，而一个透明的图标在它们上面都待得住。一个画进了白色背景的图标，在深色标签栏里就是一个白矩形。

有两个例外值得知道：

  • 一个纯深色、别的什么都没有的 logo在深色模式下会消失。如果你的标记天生就是白底黑图，那就给它一个带颜色的背景而不是透明背景，或者给它一圈浅色描边。
  • Apple touch icon 必须不透明。iOS 会把它画在自己那个圆角方块上，并把透明渲染成黑色。任何产出那个文件的工具都应该替你把它压平；这里的这一个会，默认压到白色上。

网站需要的、不是 .ico 的那些文件

favicon.ico 管的是浏览器和 Windows。它管不了手机，而大多数自制的图标套装恰恰在这里就停早了。另外三个平台各要自己的文件、按自己的名字，而它们没有一个会往 .ico 里面看：

  • iOS 在有人把你的网站添加到主屏幕时，读 180×180 的 apple-touch-icon.png。没有它，iOS 会用一张页面截图，那看起来像是出了错。
  • Android 和每一个安装提示读一个 web app manifest — site.webmanifest — 它指向 192 和 512 像素的 PNG。那个 512 也是 web 应用启动画面上显示的那一张。
  • Windows 开始菜单磁贴读 browserconfig.xml，它指向一张 150×150 的 PNG。三者中最不重要的一个，四行 XML。

还有一个很容易搞错：Android 启动器会把一个自适应图标裁成手机喜欢的任意形状 — 圆形、圆角方、圆角矩形 — 而只有图像中间那 80% 是保证活得下来的。一个画到边的图标会丢掉四个角。所谓 maskable 图标就是这个意思：同一幅画面有意识地画小一点、缩在方框里面，并在 manifest 里单独声明。

在图片转 ICO里勾上网站那一套，会把这些、那个 manifest，以及指向它们的那段 HTML 全部产出来。那段 HTML 有一样东西是刻意不写的：给 favicon.ico 的 <link>。浏览器自己就会去要那个地址，再写一遍会让同一个文件被取两次。

Windows 应用图标是另一套尺寸

如果这个图标是给一个程序、而不是给一个网站的，尺寸就变了。Visual Studio 自己默认的 app.ico 里装的是 16、32、48 和 256 — 三个外壳尺寸，加上开始菜单和资源管理器超大图标视图会用到的那个大的。

在高 DPI 显示器上，Windows 还会索取 20、24、40、64 和 96，缺了的话就从它手上最接近的尺寸重采样。这件事要不要紧取决于你的图标：一个平坦的形状撑得过重采样，一个细节丰富的撑不过。把它们加上去大约会让文件大一倍，而对一个应用来说那根本不算什么 — 这笔账和 favicon 完全不同，后者是每一个访客都要取一次的。

关于体积还有一件事：字节都堆在那个 256 的条目上。不压缩存的话它自己就是 264 KB；作为 PNG 存在图标里，通常不到 30。PNG 条目从 Windows Vista 起就能读，所以回避它们的唯一理由，是确实比那更老的软件，或者某个自己解析图标的安装程序或嵌入式工具。

Mac 读的完全是另一个文件

如果这个图标是给 Mac 应用而不是 Windows 应用的，上面那些一条都不适用：macOS 根本不读 .ico。它读 .icns，那是同一个想法换了个包装 — 一个容器里装几个尺寸 — 有三处不同值得知道。

  • 尺寸是定死的。苹果公布了十个槽位，没什么可挑的：16、32、64、128、256、512 和 1024 像素，其中 32、256 和 512 各出现两次，因为它们既是自己那一档尺寸，也是下一档的 Retina 版本。
  • 它一直做到 1024。而一个 .ico 停在 256，这就是为什么一个 Mac 图标文件有好几百 KB，而一个 favicon 只有十五 KB。对一个只发布一次的应用来说那不算什么；只有 favicon 才是每个访客都要取一次的。
  • 你的图稿必须撑得住 1024 像素。这两个问题是同一张画面的两个极端：favicon 必须在极小的时候还立得住，而 Mac 图标必须在极大的时候还扛得住。一个按 512 导出、再被放大到 1024 的 logo，在 Retina 显示器上看着发软，而 App Store 不会收它。

怎么用：应用包把它放在 YourApp.app/Contents/Resources/ 里，并在 Info.plist 中写明。对一个文件夹或者一个磁盘映像，在访达里选中那个 .icns，按 Command-C，然后对你想改的东西“显示简介”，点左上角那个小图标，按 Command-V。

在图片转 ICO里勾上 macOS 图标，就会写出一个，旁边带不带那个 Windows 文件都行。任何在两个平台上都要发布的东西，两个都要，而且两个是从同一张图片、在同一遍里画出来的。

确认它生效了

浏览器缓存 favicon 比缓存几乎任何东西都狠，所以“我传上去了但什么都没变”通常是缓存，不是出错。在你重新开始改文件之前，有两件事可以试：

  • 直接打开 https://yoursite.com/favicon.ico。如果文件下载下来了，那它就在那儿，你看到的是缓存。如果你拿到一个 404，那它不在根目录。
  • 用无痕窗口加载这个站点，那里通常有一份自己的图标缓存。

在 Windows 上，一个 .ico 可以这么核对：把它放进一个文件夹，让资源管理器在几档视图尺寸之间切换 —— 小、中、大和超大会从同一个文件里画出不同的条目，所以你能按系统的方式看到每一个。

在 Mac 上，一个 .icns 可以用“预览”打开，它会把每一个槽位列在侧边 — 同样的招数在访达里也管用：把它放进一个文件夹，拖动视图选项里的尺寸滑块，就能看着它在里面那些画面之间切换。

这些没有一样需要上传

缩放一张图片是每个浏览器做了很多年的事，而一个 .ico 就是一个六字节的文件头、每张图十六字节，然后是那些图。做一个 .ico 没有哪一步需要服务器，而这里的工具也没用一台：这个页面的 Content-Security-Policy 列出了它可能联系的每一个地址，其中没有一个属于本站。

这一点在这里比平常更值得在意。交给一个免费 favicon 生成器的 logo，相当多的时候是一个尚未发布的品牌 — 图标是最早做出来的东西之一，也是最晚公布的东西之一。与其听我们说，不如把页面加载出来，拔掉网线，照样做一个试试。把文件传给在线转换器安全吗？还列出了另外三个你可以对任何工具做的检查。
