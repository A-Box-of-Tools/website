# 如何分享文本与文件而不在服务器保存副本

移动笔记或文件，无需在邮件、聊天记录或分享服务器留下副本。默认由两个浏览器直接连接。如果无法互通，主持端可以选择云中继并新建分享，由 Cloudflare 转发加密内容。接收方仍可保存自己的副本。

[打开文本与文件分享](https://abox.tools/zh/share-text/): 从打开的浏览器加密分享文本与文件。默认直连，也可选择云中转。你可以逐一批准读者。

最后更新 2026年10月13日

## 简短做法

默认方式是 Direct。下文关于直接互通的网络说明适用于这种方式。如需使用 Cloud relay，由主机在开始前选择，并分享新的邀请。另一方在连接前查看并确认。Direct 不会自动切换。Cloudflare 转发加密内容，并可看到地址、时间和流量。使用中继时，双方需要全程联网。批准、密码和麦克风控制仍然有效。

在有内容的设备上打开[文本与文件分享](https://abox.tools/zh/share-text/)，写入文字或附上文件，选择*开始分享*。页面会给出类似 `brave-otter-42` 的名字。在另一台设备打开同一页面，把 `#brave-otter-42` 加到地址末尾，或打开复制的链接。另一端连接前会先请求，经你允许后，内容通过加密连接从一个浏览器传到另一个。关闭分享标签页，分享就结束。

分享的文字和文件没有作为副本上传到服务器。下面解释这为什么有用，以及它实际有什么限制。

![分享工具的编辑卡片。文本框中有会议笔记，上方有 Markdown 开关和添加文件按钮。](https://abox.tools/screens/share-text-between-devices/write.webp)

要交出去的内容。购物清单和文档都用同一个框，Markdown 是开关，不是独立模式。

## 把笔记送到手机，或交出活动文件

**从笔记本电脑到手机。**在电脑的分享页放入长地址、说明或文件。保持 Private 开启，在手机上打开复制的链接，批准预期读者，再复制或下载所需内容。手机接收完成前，保持分享标签页可见和唤醒，之后结束分享。手机已保存的副本不会随链接结束而消失。

**现场工作坊或支持通话。**双方都在场时，分享练习文件、示例配置或诊断片段。尽量用虚构数据，逐一批准读者。可发现的 Local network 模式中，出现在列表里不证明对方在同一房间。单个文件不能超过工具的 200 MB 限制。

预约前在实际网络上试连接，并为阻止直连的网络约定备用办法。这是实时交接。无人值守的隔夜传送，应有意选择会保存内容的服务。

## 常见办法会在哪里留下副本

给自己发邮件，笔记就存在已发送和收件箱里，还会同步、备份，多年后仍能搜索。把密码粘贴进聊天，会留在历史和云备份里。用粘贴板网站或文件投递服务，内容放在服务器上，由到期设置和删除按钮控制。这些方式都把存储作为分享的一部分。

有时你就是需要一份等对方准备好的副本。但快速分享往往双方都在，内容只用一会儿。访客 Wi-Fi 密码、电话里读到的地址、需要别人检查的错误信息、送到目标设备的配置片段，都未必需要归档。

## 直接连接是什么意思

工具使用 WebRTC，和浏览器视频通话一样。双方建立加密通道，通过不经服务器的直接路径发送内容。有可用本地连接的两台设备可以利用网络本身的速度，实际路径也受 VPN、浏览器策略和网络设置影响。

有一个必须说明的例外。两个浏览器不能自行找到彼此。小型 rendezvous 服务器匹配输入名称的读者与分享者，并转发几千字节的连接设置。它不保存分享内容，直连内容也不经过它。服务源码与工具一起公开。它还展示自愿列出的本地链接名，方便另一端在首页发现分享。这个介绍服务由本工具和 Remote Camera 使用。可选图片获取、收据汇率查询和平台脚本各有网络边界，见[隐私页](https://abox.tools/zh/privacy/)。分享工具说明了介绍服务能看到什么。

直接连接也意味着双方都会知道对方的网络地址。读者在连接前会看到说明，只有主动选择才会连接。

## 在同一个 Wi-Fi 或以太网上分享

Local network 默认关闭。开始前选择 *Local network — no internet relay*，附上文件。需要逐一批准时，保持 Private 开启。Discoverable 默认勾选。在第二台设备打开工具，检查*可用连接*中的连接类型，然后选择名称旁的加入。系统会打开阅读标签页并发起请求。私密分享会等待你批准。只想通过链接分享时，开始前取消 Discoverable。双方需要在同一个 Wi-Fi 或以太网上。文件仍有 200 MB 限制，读者仍自己选择下载哪些文件。

列表按介绍服务器看到的公共 IPv4 地址或 IPv6 子网分组。通常是同一路由器，但共享 VPN 或运营商共用地址也可能把其他网络列进来。IPv4 与 IPv6 混用或路径不同，也可能让身边设备不出现。在共享网络上保持 Private。列表名称对同组其他人可见，不证明设备在同一房间或建筑。仍需要联网。发现功能不可用时，复制的链接仍可使用。

复制链接带有 `?local=1#brave-otter-42` 设置。口述名字时，也要告诉对方使用 Local network。只有 `#brave-otter-42` 会请求普通模式。如果读者和分享者模式不同，页面会解释，并在按分享者模式尝试前要求选择。

本地模式不用公共地址发现服务器，也不提供互联网中继。但浏览器介绍仍需要联网。访客 Wi-Fi 隔离、防火墙、VPN 和浏览器网络策略，都可能阻止连接或改变路径。这个模式控制寻找直接路径的方式，不证明路径始终在同一建筑内。

## 名称是地址，Private 决定谁能进入

`brave-otter-42` 可以隔着房间喊、在电话里说，或写在白板上。另一端容易输入，这就是采用这种名称的原因。

知道或猜中有效名称的人都能打开分享。可发现的本地分享会向同一公共 IPv4 地址或 IPv6 子网的浏览器列出名称，所以在这个组内名称是公开的。敏感内容保持默认的*私密*，不要取消勾选。每位读者要先自我介绍，再由你逐个批准。介绍通过加密直连传输，rendezvous 也看不到是谁请求。

![链接名称卡片显示 thursday-notes，以及私密和一次性分享开关。](https://abox.tools/screens/share-text-between-devices/name.webp)

名称就是地址。私密表示每位读者都要请求并获你批准。一次性表示设备也不保留草稿。

## 关闭标签页会结束什么

分享存在于分享标签页里。关闭标签页会实际结束它，不只是请求服务器删除。链接几秒内失效，仍在观看的读者页面会清空。没有服务器副本、回收站或三十天保留期。输入草稿默认留在自己的浏览器供下次使用，也可以用一次性设置关闭。

它不能撤回已交出的副本。读者在分享期间复制了文字或下载了文件，就已经拿到了。没有工具能替别人设备撤回内容。结束分享只控制未来，不再接受新读者，不再发送更多内容。

## 在线面试很适合实时交接

面试时双方已在场，适合实时交接。会议聊天可能进入转录和录像；共享屏幕时打开邮件或聊天找链接，还可能让私人通信进入他人的录像。分享页面只展示要交出去的内容。

作品集链接、代码仓库、带回家的 PDF，或可能被聊天框智能引号改坏的代码片段，都可以在通话前开始分享，需要时口述 `brave-otter-42`。保持私密，就能在通话中批准面试者进入。通话结束后关闭标签页，分享也结束，不把内容留在会议转录里。但对方自行保存的副本仍存在。

面试者可能使用严格的公司网络，少数网络组合没有直接路径。你无法在家测试对方网络，但工具会在二十秒内报告失败，不会一直卡住，方便及时换备用办法。

## 什么时候不适合用它

双方必须同时在线，分享标签页需要保持打开。分享需要网络，只有编辑部分可以离线使用。如果 Direct 在移动网络或公司网络上失败，主机可以停止分享，选择 Cloud relay 后重新开始，再发送新的邀请。读者在连接前确认连接方式。本地 Direct 不使用中继。浏览器休眠和公司网络策略也可能中断中继连接。

对于双方都在场的笔记、密码、配置文件，或相隔一个 Wi-Fi 连接的 100 MB 视频，直接交接通常更快、更简单，也不在服务器上留下分享副本。
