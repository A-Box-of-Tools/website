# 普通文件会透露你的哪些信息

文件不必有密码或“机密”标签，也可能透露个人信息。决定分享哪份副本前，先看内容、情境和受众。

最后更新 2026年10月22日

## 先考虑谁会收到文件

同一份文件，对一个接收人可能合适，对另一个人却可能透露太多。报销审核人也许需要收据上的日期和商户，但在公开问题中讨论价格的人，通常不需要你的会员编号或确切到店时间。

姓名只是检查的一部分。细节与接收人已经掌握的信息结合后，也可能识别某个人。英国信息专员办公室在[个人信息指南](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/personal-information-what-is-it/what-is-personal-information-a-guide/)中解释了这种与情境有关的判断。

下面的例子都是虚构的。每个例子都先说明分享的理由，再看还有什么信息会一起传过去。

## 收据透露的不只是价格

假设有一张 North Street Print 的收据，上面写着 CAD 12.40 的消费、分店地址、时间戳、会员编号和顾客邮箱。你想把它发到社区讨论中，聊聊打印成本。

品名、数量和价格足以解释成本。邮箱把交易与一个人联系起来，分店和时间戳给出了可能的位置和时间，会员编号又增加了讨论并不需要的身份标识。

这些并不能证明一个人的习惯，甚至不能证明订单是本人领取的。要区分文档明确写了什么，以及读者可能推断出什么。一次消费不能可靠地描述某人的日常规律。

公开讨论时，准备一份保留足够价格背景的副本。报销时，则保留审核人要求的交易细节。原件单独保存，不要因为制作分享副本而破坏自己的记录。

## 截图也包含周围环境

假设截图显示上传文档时的错误。错误周围还有账号邮箱、求职申请的浏览器标签页、同事发来的通知，以及含有客户姓名的文件名。

支持人员需要弄清哪里失败了。文件名也许有助于说明文件类型，但客户姓名可能毫无作用，通知则与问题无关。公开论坛的受众，也比私下的客服对话广得多。

从一边到另一边读完整张截图，不要只盯着错误。检查标签页标题、侧栏、账号菜单、文件名、地址和通知。确定哪些细节能说明问题，例如错误提示、相关控件和文件扩展名。

保留这些上下文。如果除了一个没有解释的错误编号，其余全部去掉，截图可能失去用途，还会让对方再问一次。

## 出席名单也在描述人与人的联系

一份虚构的工作坊表格包含姓名、联系地址、出席标记，以及某人未能参加的原因备注。组织者需要联系缺席者，资助方则想知道有多少人出席。

这是两个不同的用途。组织者也许需要个人记录，资助方要一个人数，并不自动意味着需要每位参与者的地址或缺席原因。实名名单把人与活动、地点和日期联系起来，无论作者自己觉得这种联系重不重要。

只删掉姓名，也可能留下能认出人的组合。如果大家都知道只有一位志愿者来自某个单位，这个描述仍可能指向那个人。应检查汇总结果，不要假设删除一列就完成了匿名化。对别人的信息，也要像对自己的信息一样仔细检查。

## 不只看页面上显示的内容

对某些文件格式来说，可见内容只是一部分。Microsoft 说明，Office 文件可能包含作者属性、批注、修订记录和隐藏的电子表格内容。接收人拿到的文件里，仍可能包含隐藏工作表。参见 Microsoft 的[文档检查说明](https://support.microsoft.com/en-gb/office/collab-files/remove-hidden-data-and-personal-information-by-inspecting-documents-presentations-or-workbooks?nochrome=true)。

如果拍摄时记录了位置，照片也可能带有位置元数据。Apple 在[位置元数据说明](https://support.apple.com/en-gb/guide/personal-safety/ips0d7a5df82/1.0/web/1.0)中解释，接收含有这类信息的照片后，对方可能知道照片在哪里拍摄。

用合适的查看器或创建文件的应用，检查实际文件。这些例子不意味着每张照片都有坐标，也不意味着每份文档都有隐藏批注。要检查具体有什么。[PDF 记住了什么](https://abox.tools/zh/guides/what-a-pdf-remembers/)和[照片元数据](https://abox.tools/zh/guides/remove-exif-and-gps-data/)指南更详细地解释了这两类格式。

## 编辑前，先列一份简短检查计划

1. **写明用途。**补全这句话：这位接收人需要用这份文件做什么？写得足够具体，才能判断某项细节是否有帮助。
2. **明确受众。**区分单个审核人、一个团队和公开页面。考虑接收人是否预计会继续转发。
3. **列出所含内容。**检查可见内容、文件名、文档属性，以及这种格式支持的附加内容。
4. **考虑信息组合。**想一想，接收人把这些细节与已经知道的信息联系起来，还能了解什么。
5. **标明保留或删除。**保留理解证据所必需的细节。在删除重要内容之前，先澄清不确定的要求。
6. **检查最终副本。**重新打开实际准备发送的文件。确认它仍能回答接收人的问题，所做修改也确实进入了输出。

## 保留足以完成任务的信息

目标是制作一份有用、披露适度的分享副本。信息专员办公室的[数据最小化指南](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-protection-principles/a-guide-to-the-data-protection-principles/data-minimisation/)在限制信息量与满足既定用途之间作出平衡。把这种检查原则用于眼前的文件和受众。

价格要连同数量和币种保留，错误要保留诊断所需背景，出席人数则要与对应的活动和日期一起提供。明确应该留下什么之后，再选择合适的编辑或元数据工具。对于图片，[涂黑指南](https://abox.tools/zh/guides/redact-an-image/)解释了删除方式和输出检查。分享前，把最终文件与自己的计划逐项核对。
