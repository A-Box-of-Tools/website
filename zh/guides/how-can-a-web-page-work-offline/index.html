网页断了网怎么还能用？

因为浏览器留了一份完整的副本，还有一个随页面一起送达的小程序，网络帮不上忙的时候就端出这份副本。这套机件是标准件，值得弄明白：一个断着网还照常干活的工具，给你看的是任何隐私政策都给不了的东西。

最后更新 2026年8月26日

先说结论

网页通常和它的连接同生共死，因为每次访问都要把它重新取一遍。但页面可以随身带一个小程序，叫 service worker。浏览器把它安在页面旁边，让它掌管页面的网络往来。头一次访问时，这个 worker 就把组成页面的一切，标记、样式、脚本，完完整整存进你机器上的一份缓存。从那以后，请求都由这份副本来答。Wi-Fi 断了，什么也不变，反正本来就没在取什么。

这里没有魔法，也不需要什么特殊许可：这是浏览器的标准机件，装进各大浏览器差不多十年了。少见的是像这个站这样把全身重量都压上去的站。对一个全部承诺就是“你的文件永不出门”的站来说，离线不是舒适性配置。它就是证明。

拔了线还活着，说明了什么

上传那一页最硬的一条检查就是拔网线：把工具打开，断网，接着用。这一招为什么灵，值得说透。在服务器上转换你文件的工具，恰恰在干活的那一刻离不开网络。线一断，活就停。断网还照干的工具，不是宣称、而是当场演示了活儿就在你机器上干；而一个够不着网络的页面，代码再想也没法把你的文件送去任何地方。

这是任何隐私政策都给不出的东西。政策写的是打算，打算会改；飞行模式里照常干活的页面，是物理。所以这个站的每个工具都能离线用，页面上还带一个实时指示，告诉你此刻在不在线。你可以一边开关网络一边看它翻面，用十来秒钟跑完世上最硬的那条检查。

副本怎么保持老实

永久保存是礼物还是陷阱，由两个问题决定，这套机件把两个都答了：

  • 副本会不会放陈？有连接的时候，worker 会去看有没有新版本，有就整个换掉。版本整个换，是因为副本必须时刻自洽。半旧半新，是唯一一种绝不能端出来的状态。
  • 存的到底是什么？页面需要的一切，多一件没有。而且这里每个工具的副本都放在自己的格子里：一个工具的缓存装的就是那个工具，装一个不会悄悄装十个。副本还经得起查看：浏览器的开发者工具能列出缓存里的每个文件，那份清单和页面当初光明正大取来的清单一模一样。

结果就是一个页面，表现得像一个你逛了一趟就装好的应用。而这也是明码标价的服务：浏览器的地址栏能把这里任何一个工具装成应用，用工具自己的图标，一开就直达工具，页面上没有按钮，也没有讨要权限的脚本。同一套机件，穿了件快捷方式的衣服。

离线证明不了什么

这条检查够硬，但不是魔法。它的边界值得说得和它的力气一样清楚：

  • 它证明的是那一刻，不是以后。离线干的活留在了你机器上，就这些。页面原则上可以把数据攥着，等连接回来再发。所以最要紧的文件，重新联网之前先把标签页关掉；或者把另一头也查了：连接恢复的那一刻，盯住网络面板。
  • 它证明的是这一页，不是整个站。每一页各自为自己作答。这里唯一用网络的那一页，把这件事写在了自己页面上：文本分享工具，它的全部工作就是在两台设备之间递东西，它唯一的一条连接运的是什么，页面上讲得明明白白。
  • 它藏不住你。把页面加载进来这件事本身，就已经把你的地址告诉了网站，和网上每一次加载页面一样。离线管的是你的文件去哪儿，不管匿名。

正是这些边界，让上传那一页教的是四条检查而不是一条：网络面板、页面源码里的安全策略、读得了的代码，补上了拔线补不上的那部分。但论第一道筛子，没有比它更快的：一个工具断了网干不了活，你就已经知道活儿在哪儿干了，后面的都不用再读。
