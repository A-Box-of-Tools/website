● 你的图片不会被上传。这里根本没有服务器。

缩放和图标文件本身，都是在你自己的浏览器里做出来的。画面由浏览器本来就带的 canvas 绘制，Windows 的 .ico 和 macOS 的.icns 这两种容器，则由 src/ico.js 和src/icns.js 里两百来行你读得懂的代码，从那些像素拼出来。这个工具没有任何形式的网络功能，没有什么可取，也没有什么可发，何况页面的另一端根本就没有服务器，想送 logo 也没地方送。

不用信我们说的。打开开发者工具，盯着“网络”面板，做一个图标试试。没有哪个请求带上图片、缩略图、文件名，或者你选中内容里的任何一个字节。嫌麻烦就直接拔掉网线，照样做。

隐私这一条要怎么验证

  • 你的 logo 无处可去。Content-Security-Policy 把这个页面允许联系的地址全列了出来，其中没有一个属于本站。这里没有能收你文件的接口，代码里也没有一行会去发送文件，就算真有那么个接口也一样。
  • 这里没有任何东西会去联网取数据。src/ 里找不到 fetch，找不到XMLHttpRequest，也找不到 sendBeacon。缩放就是往 canvas 上做一次 drawImage，图标就是src/ico.js 或 src/icns.js 在这个页面里，给那些像素前面写上一个文件头。
  • 这个文件是用它自己的字节来描述的。做好的图标旁边列出的尺寸清单，不是你要求的那份清单，而是readIcoDirectory 或 readIcnsElements 从刚写出来的那个文件里重新读出来的。万一写入的结果和设置对不上，页面当场就说出来，不用等 Windows 什么都不画、macOS 画出一张白纸你才发现。
  • Google 加载了什么，又拿不到什么。广告脚本和统计脚本来自 Google，捐助按钮来自 Buy Me a Coffee。关于你图片的信息，一条也没有交给它们。读取、缩放、写出文件的每一行代码都由这个源提供，也都摆在仓库里。
  • 断网也照样能用。断开网络，这个工具跟原来一模一样，因为它里面从来就没有联网这一步。这是最省事的一条证明。

你可以自己核对。上面这些都不用你凭信任接受。这个页面是 仓库里的模板和配置，经过一个你能读、也能自己跑的构建脚本生成出来的， 结果提交在 dist 分支上，所以你可以拿实际提供的内容和从源码 构建出来的结果直接对比：

github.com/A-Box-of-Tools/website

最值得先读的几个文件：config/site.toml 里是 Content-Security-Policy，src/ico.js 和 src/icns.js 里是这两种图标格式，一个讲目录、条目和掩码，另一个讲苹果那十个具名槽位，src/sizes.js 里则是页面上每一个尺寸的来历。

      怎么做一个 .ico 文件，而且什么都不上传
       
         
      1.  选那张图。把 PNG、JPEG、WebP 或者 SVG 拖到下面的方框里，也可以一次挑好几个一起转。正方形最省事，256 像素以上的图细节足够撑起每一个尺寸。浏览器直接从你的硬盘上读，整个过程没有东西被送去别处。 
        2.  
      2.  挑你需要的那些文件。Windows 和浏览器读 .ico，Mac 读 .icns，而且根本不看另一个。勾一个，两边都要发就两个都勾。网站还要额外的 Apple、 Android 和磁贴图片，那是第三个勾选框。 
        3.  
      3.  说明这个图标是干什么用的。网站 favicon 要 16、32 和 48 像素，Windows 应用还要 256，要在高 DPI 笔记本上看着不糊，就还得加上 Windows 在 125% 和 150% 缩放下索取的那几个中间尺寸。挑一个跟你的活儿对得上的，或者自己勾尺寸，清单上每一个尺寸都注明了谁在要它。.icns 没有这种选择，苹果明确规定了十个槽位，十个全都得进去。 
        4.  
      4.  处理形状和背景。图标是正方形，大多数 logo 不是。留白会保住整张图，上下留出空间；裁剪只取中间那块；拉伸会把它挤变形。透明会当作透明保留，除非你选一个颜色垫在后面。 
        5.  
      5.  下载之前，先看一眼 16 像素那个。那是这个图标被看到最多的尺寸，也是细线条和小字消失的地方。预览里每一个方块都按真实尺寸、从你自己的文件画出来。最小的那个要是糊成一团，解法是换一张更简单的图，不是换一个设置。 
        6.  
      6.  把文件拿走。一个把所有尺寸都装在里面的 .ico，你要的就是这个的话，它会叫favicon.ico，因为那是浏览器会去找的地址。勾了 macOS，旁边还有一个 .icns，可以直接放进 Mac 应用包里。再勾上网站那一套，你还会拿到 Apple、Android 和 Windows 磁贴图片、manifest，以及一段能粘进你页面的 HTML。只要不止一个文件，就打成一个 zip 下来。

      常见问题
       
       
       我的图片会被传到什么地方去吗？ 
       不会。画面由你自己的浏览器在你自己的硬件上解码和缩放，.ico 则由这个页面提供的代码从那些像素拼出来。这个工具没有任何形式的网络功能，从不取什么，也从不发什么，而页面的 Content-Security-Policy把它可能联系的地址全列了出来，其中没有一个属于本站。 
       
       
       一个 favicon.ico 里应该装哪些尺寸？ 
       16、32 和 48。这不是偏好问题。16 是浏览器在标签页里画的那个，32 是 Windows 用于桌面快捷方式、也是好几个浏览器用于书签的那个，48 是 Google 读取站点图标时用的尺寸。比这更大的应该放在 .ico 旁边的 PNG 里，而不是塞进 .ico 里面，这里的网站那一套做的正是这件事。 
       
       
       一个 Windows 应用图标需要哪些尺寸？ 
       16、32、48 和 256，也就是 Visual Studio 自己默认的 app.ico 里装的那几个。16 用于标题栏和资源管理器的小图标视图，32 用于桌面和任务栏， 48 用于资源管理器的中等图标，256 用于开始菜单和超大图标视图。高 DPI 显示器上，Windows 还会索取 20、24、40、64 和 96，没有的话它就从最接近的尺寸重采样，选“覆盖所有缩放”那个预设，会把它们都放进去。 
       
       
       为什么文件比我原来那张图还大？ 
       因为一个 .ico 不是一张图，是好几张，而且小尺寸不压缩存放，好让什么东西都读得了。一个 32x32 的条目不管里面是什么，都正好是 4,264 字节，一个 256x256 的不压缩条目则是 264 KB，所以 64 以上的尺寸默认存成 PNG。选“所有尺寸都用 PNG”得到的是最小的文件，选“所有尺寸都不压缩”得到的是兼容性最好的那个。 
       
       
       PNG 条目和不压缩条目有什么区别？ 
       区别只在于像素在 .ico 里怎么存。不压缩的条目是 Windows 最初那套安排，一个位图头、上下颠倒的像素，加一张一位的透明掩码，任何一个发行过的 Windows 版本都读得了。PNG 条目是把一整个 PNG 文件塞进图标里，大尺寸上要小三到十倍，但从 Windows Vista 起才被认得。默认设置让两者各用各的强项，64 像素以内不压缩，以上用 PNG。 
       
       
       它能做比 256 像素更大的图标吗？ 
       不能，谁都不能。这个格式用一个字节存每条边的长度，而 0 已经被占用了，它表示 256。这就是天花板，所以一个装着 512 像素图像的 .ico 不是更大的图标，是一个坏掉的图标。要 512，你需要的是 PNG，网站那一套里就为 Android 和 web 应用的启动画面准备了它。 
       
       
       它会保留透明吗？ 
       两种条目都会，而且它还会在 alpha 通道旁边写上那张老式的一位掩码，好让老到读不了 alpha 的软件仍然能把图标抠出来，而不是画一个黑方块。唯一一个故意做成不透明的文件，是网站那一套里的 Apple touch icon，iOS 会把它合成到自己的方块上，并把透明变成黑色，所以它被压平到你选的背景色上，默认是白色。 
       
       
       我的 logo 是一个横排的文字标，会怎么样？ 
       总得有点变化，因为图标是正方形。留白会把整个东西保下来，然后让它变得很小，一个文字标塞进 16 像素的方块里大概只有三个像素高，根本认不出来。裁到中间通常效果更好，把符号从整个组合标里拿出来单用，几乎每个品牌的 favicon 都是这么干的。预览会在你下载任何东西之前，先告诉你哪一个活得下来。 
       
       
       网站那一套里有什么，我全都需要吗？ 
       七个 PNG、一个 web app manifest、一个 browserconfig.xml，以及一段能直接粘的 HTML。你需要它们，是因为一个 .ico 只管浏览器和 Windows，别的一概不管。iPhone 的主屏幕读的是一个 180 像素、名字自成一格的 PNG， Android 和每一个安装提示读的是 manifest，钉在开始菜单上的磁贴读的是那个 XML，它们没有一个会往 .ico 里面看。所有东西都在这里、在你的机器上生成，zip 里还附了一张说明，写清楚每个文件是干什么的。 
       
       
       它也能做 macOS 图标吗？ 
       能，勾上 macOS 图标，你会在 .ico 旁边拿到一个.icns，或者干脆只要它。它是同一个想法的另一种容器，两个系统谁也不读对方的，Windows 要 .ico，Mac 应用包要 .icns。那边的尺寸不是选择题，因为苹果明确公布了十个槽位，16、32、64、128、256、512 和 1024 像素，其中三个会出现两次，作为下一档的 Retina 版本。十个全都进去，由七次渲染画出来，这也是 .icns 更大的原因。 
       
       
       这个 .icns 文件怎么用？ 
       给应用用的话，它放在应用包的YourApp.app/Contents/Resources/ 里，并在Info.plist 的 CFBundleIconFile 下写明，每一个 Mac 打包工具都有对应的字段。别的用途也简单，在访达里选中这个文件按 Command-C，然后对你想改的文件夹或者磁盘映像“显示简介”，点左上角那个小图标，按 Command-V。 
       
       
       这个 .icns 和 iconutil 做出来的一样吗？ 
       一样的十个槽位、一样的四字母类型，每个里面装的都是 PNG，也就是iconutil 从一个 .iconset 文件夹生成出来的东西。有一处是故意不同的，苹果的工具还会写一个 TOC 元素，那是后面那些类型和长度的一份索引。它是一项优化，不属于格式本身，没有它的读取器会从头到尾走一遍元素，得到同样的答案，而一个错的索引比没有索引更糟，所以这里干脆省掉。 
       
       
       我能一次转好几张图吗？ 
       能。列表上每一张图都会用同一套设置变成它自己的 .ico，这一批打成一个 zip 下来，每张图一个文件夹，不然其中两个都会叫 favicon.ico，一个会把另一个盖掉。你勾选的每一种输出，都会为每一张图生成。点任意一行，就能把那张图放进预览。 
       
       
       它免费吗，需要注册吗？ 
       免费，没有账号，不用登录，没有试用期，也没有水印。文件的数量和大小同样没有上限，因为没有哪台服务器在为它们掏钱，活是在你自己的机器上干的。本站带广告，经费就是从那儿来的，广告拿不到任何关于你图片的信息。 
       
       
       断网能用吗？ 
       能。页面加载一次之后断开网络，它照样干活。这也是证明“什么都没上传”最省事的办法，真要把你的 logo 送出去转换，拔线那一刻就停了。
