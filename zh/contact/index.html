联系

读信的是一个人，而且每封都读。下面写的是这两条路各自适合什么、一份缺陷报告要写上什么才真能被找出来，以及你发出去之后会发生什么。

最后更新 2026年8月27日

两条路

邮件，hi@abox.tools。直接寄到写这些工具的人手里。凡是你不太想摆到明面上说的事，走这条路：一桩隐私上的顾虑，一项版权或商标方面的主张，一个安全问题，或者一个非得附上别人不该看的文件才说得清的缺陷。

问题追踪页，github.com/A-Box-of-Tools/website/issues。看的是同一个人。凡是别人也能跟着受益的事，走这条路：某个工具处理不好某一类文件，某句译文在你的语言里读着不对，一个功能建议，或者一个答案该留在下一个人找得到的地方的问题。这条路要有 GitHub 账号，邮件不用。

没有电话，也没有在线客服。这是一个人的项目，摆一条没人坐守的热线，比直说更糟。

你写完之后会发生什么

有人会读，通常在几天之内。回信用英文。

一个能复现的缺陷，通常一两周内修好，修复会出现在公开的提交记录里；要是你是以 issue 的形式提的，你的报告也会挂在旁边。功能建议会得到一个诚实的答复，有时候这个答复是不行。ROADMAP.md 给每一个被否掉的想法都留了一段，写明为什么，所以这里的“不行”是带着理由来的。

不会发生的事：你不会被加进任何邮件列表，你的地址也不会给任何人。它只用来回你的信，别的都不用。

怎么把缺陷说清楚，好让人找得到

这些工具跑在你的机器上，不在服务器上，所以这边没有日志可查。发生过的一切都发生在只有你能看见的地方。因此一份写明了是哪个页面、哪里不对的报告，在这里比在几乎任何别处都值钱。有用的细节是这些。

  • 哪个工具，把地址带上。一共三十六个，其中好几个干的活儿挨得很近。
  • 浏览器和版本，以及是不是手机。这类缺陷里有相当一部分，其实是某个浏览器对视频容器或者图像编码器的理解，而不是工具本身的毛病。
  • 那个文件是什么：格式，大概多大，从哪来的，比如是哪台相机或者哪款手机。文件本身不用发过来。要是刚好有一个不涉及隐私、又能复现问题的小样本，那帮助极大；没有的话，描述一下通常也够了。
  • 你以为会得到什么，实际得到了什么。“没反应”和“导出的片子没有声音”是两个缺陷，原因也不一样。
  • 浏览器控制台里飘红的东西，前提是你知道怎么打开它。把第一条错误复制过来，比把满屏截下来更有用。

安全和隐私方面的报告

这类事情走邮件，别公开发：hi@abox.tools。凡是能让这里的页面碰到它本不该碰的文件、把文件送到什么地方去、或者执行没有下发给它的代码的问题，都会被认真对待，并在同一周内看。隐私页说不收集、而站点实际上收集了的任何情况，也一样。

没有漏洞赏金计划，也没有钱。这话与其让人干完活才发现，不如先说明白。提交记录和版本说明里的署名可以给，你不要也一样痛快。

版权、商标和下架请求

本站没有用户上传的内容，这里也没有任何地方可供谁发布东西：工具是在访客自己的浏览器里处理文件的，访客打开的和做出来的，都到不了本站。所以没有托管的内容可以下架，也没有账号可以封停。

但如果本站自己写的、画的东西，一个页面、一张插图、一段代码，侵犯了你的权利，请写信到 hi@abox.tools，附上那个页面的地址和具体是哪一处，会直接处理。

广告与商务来信

本站通过 Google 展示广告，合作就到此为止。直接投放、软文、付费链接、投稿和交换链接，一律谢绝，原因不是清高：一个悄悄替别人带话的页面，读者已经没法掂量它说的话了，而本站的每一句话都是请读者去核实的。这封邮件就省了吧。

把这些工具用在生意上不需要许可，也不需要授权：任何用途都可以随便用，包括在公司里用。复用代码则按仓库里的许可证来，那份许可证很宽松，把某个模块整块搬走，正是它存在的意义。

你在写给谁

abox.tools 是一个独立、自负盈亏的项目，由一个人在加拿大安大略省经营。它不是公司，上面那个地址背后也没有客服部门。回信比公司慢，原因在这里；回信是由读过代码的人亲手写的，原因也在这里。关于页写了这东西是谁做的、工具为什么是这个样子，以及站点的开销从哪来。
