在每台电脑上选择文件夹

在两台电脑上都打开文件夹同步。电脑上的 Chrome、Edge 和其他大多数 Chromium 浏览器，既能读取文件夹，也能写入文件夹，双向同步需要的正是这一点。把两台电脑连到同一个 Wi-Fi、以太网或手机热点，并保持联网。浏览器要靠互联网找到彼此，但文件从不经过互联网。

在每台电脑上点击选择文件夹，选出要保持一致的文件夹。浏览器询问是否允许页面修改这个文件夹时，如果这台电脑要接收文件，就选择允许。然后选定这台电脑做什么：发送和接收、仅发送或仅接收。选择仅发送时，另一台电脑可以从这个文件夹复制文件，但永远不能修改它。每台电脑都只按自己的选择执行，不管另一台提出什么要求。

有些文件永远不会同步，页面会把它们列在文件夹下方。其中有 Thumbs.db 和 .DS_Store 这类系统自动生成的杂项文件，有临时副本和锁文件，还有 Windows、macOS 或 Linux 中任何一个无法保存的名称，比如含有冒号的名称。复制这些文件，会在另一台电脑上生成被弄坏或被误读的文件。

在一台电脑上发起，从另一台加入

在第一台电脑上选择发起同步，复制同步链接。在第二台电脑上打开这个链接，愿意的话加一条备注，再选择请求同步。然后在第一台电脑上批准请求。批准之前，任何一个文件夹的信息都不会发送，两个浏览器交换的只有建立连接所需的内容。

如果在两台电脑之间复制链接不方便，可以在第一台电脑上发起之前，勾选在可用连接中显示。第二台电脑选择查找连接，再选择对应邀请码旁的加入。列表里只有随机邀请码，从不出现文件夹名或文件名，而且仍然需要批准。

同步之前，先看比较结果

获批后，每台电脑都会把文件夹里每个文件的路径、大小和日期发给对方。两边从各自的角度，显示同一份差异清单。只在一台电脑上的文件，会复制到另一台。两边都有、但一边改过的文件，会被较新的副本替换。大小相同、日期不同的两个文件，会先比较内容，所以相同的副本不会再发送一次。

有两类行会一直保持原样，直到你做决定。一个文件在两台电脑上内容不同、日期却完全相同，就没有较新的一份，所以工具不会替你选。名称只有大小写不同的文件，比如 README.md 和 Readme.md，在 Windows 和 Mac 上是同一个文件，复制哪一个都可能覆盖另一个。把其中一个改名，再重新比较。

其他每一行都在菜单里显示默认处理方式，你可以改成发送过去、复制到这里或保持原样。列表上方的合计会跟着你的选择变化。确认无误后，在任一台电脑上选择立即同步。

有意不删除任何文件

如果你在一台电脑上删掉了一个文件，比较时会看到一个只在另一台电脑上的文件，并提议把它复制回来。没有上次同步的记录，就无法分辨文件是被删掉的还是新建的，猜错就会毁掉工作成果。把那一行设为保持原样，或者在同步之前，把这个文件在两台电脑上都删掉。

要替换的文件会先写入临时副本，全部到达后才取代旧文件。不论是取消同步、关闭页面还是连接中断，每个文件要么是旧版本，要么是新版本，绝不会新旧各半。中断前已经完成的文件都会保留。

哪些内容会经过网络

文件列表、内容指纹和文件本身，都通过两个浏览器之间直接建立的加密 WebRTC 连接传输。没有中转，也不上传，这也是两台电脑需要处在能互相访问的网络中的原因。引介服务 rendezvous.abox.tools 能看到让浏览器连上的准备消息，包括它们的 IP 地址和邀请码，但连一个文件名也看不到。

另一台电脑确实能看到你所选文件夹里每个文件的名称、大小和日期，包括不会被复制的文件。请选择你真正想共享的那个文件夹，而不是它的上一级文件夹。

浏览器无法写入文件夹时

Firefox 和 Safari 可以选择要发送的文件夹，但无法写入文件夹。它们收到的文件会汇集成一个 ZIP，上限 512 MB，由你保存后自己解压，覆盖到文件夹里。完全不能选择文件夹的浏览器（大多数手机上就是这样），仍然可以把另一台电脑的文件接收为 ZIP。

如果两台电脑连不上

确认两台电脑在同一个网络上，而且这个网络允许设备互相访问。访客 Wi-Fi 常常会隔离接入的设备，防火墙、VPN 和公司管理的工作电脑也可能阻止直连。让两台电脑都连上同一个手机热点，能很快排除网络方面的原因。

以后再次同步

保持两个页面开启，文件夹有变化时就选择重新比较；也可以停止，改天再发起新的同步。网页无法设置文件的修改日期，所以收到的文件带的是写入时的日期。下次比较会检查它们的内容，内容相同的副本视为已经一致。
