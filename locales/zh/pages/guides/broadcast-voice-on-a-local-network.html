先在说话的电脑上启动

下载工具的本地 ZIP，解压后，在文件夹内用 Python 3.10 或更高版本运行 python helper.py。不需要安装其他软件包。保持辅助程序窗口打开。在这台电脑上打开程序打印的 http://localhost: 主持端邀请地址，选择 Start channel，并允许麦克风访问。

邀请听众

在主持端选择要用的网络地址，分享听众链接或二维码。手机和电脑可以通过互相可达的 Wi-Fi 或以太网收听。听众端不会请求麦克风。页面会尝试自动播放；如果浏览器阻止声音，用已有的 Unmute 控件开始收听。听众只有 Mute/Unmute 和 Leave 两种控件。

按住说话

用触屏或鼠标按住 Talk，或者先让按钮获得焦点，再按住空格键。松开就停止发送语音。Tap to talk 可以点击开始、再次点击停止。主持端静音优先于这两种说话方式。保持主持页面可见、电脑唤醒，隐藏页面会释放麦克风采集。

最多连接十位听众，正在连接中的也计入。主持端为每位听众分别发送一条流。先从少数人开始，在实际要用的电脑和网络上测试。

恢复失去连接的主持端

主持端断开后，听众显示 Reconnecting。页面处于活动状态时，会以一秒为目标间隔原地检查连接，保留原来的静音选择。通过仍在运行的辅助程序打开同一个主持端邀请，重新启动即可恢复。浏览器在后台或设备休眠时，重试可能延迟。

End broadcast 会释放麦克风，并主动结束会话。Leave 会停止一位听众的收听和重试。重启辅助程序会生成新邀请，需要重新分享听众链接。

使用可信的网络

持有听众链接、又能访问辅助程序的人都可以加入。WebRTC 加密语音，但辅助程序使用 HTTP 传递连接设置和邀请凭据。局域网中的主动攻击者可以观察或修改这段设置过程。下载包没有远程脚本或资源，辅助程序也不接收音频。工具没有录音功能，不使用公共中继；接收者仍可以自行录下听到的内容。

检查设备能否互相访问

检查防火墙的专用网络权限、所选局域网地址，以及浏览器的本地网络权限。访客 Wi-Fi 可能隔离设备，VPN 和操作系统路由也可能影响主持端地址。自动发现漏掉网络接口时，运行 python helper.py --address 192.168.1.20，把示例地址换成这台电脑实际的专用 IPv4 地址。
