短答案

打开图片压缩，把照片拖进去，输入别人给你的那个数字，按按钮。它会把图片编码好几次，留下塞得进你目标大小的最好那个结果，并告诉你这一下的代价。对大多数照片和大多数目标来说，老实讲就一句话，你看不出差别。

这页剩下的部分，是给事情没这么顺利的时候准备的。结果看着发软，PNG 几乎纹丝不动，或者你想在把图片发给别人之前，先弄清这个工具到底对它做了什么。

一个文件大小限制真正在要求什么

JPEG 或 WebP 存的不是你的照片。它存的是这张照片的一份描述，而质量设置决定了这份描述可以有多详细。把它调低，文件就变小，因为描述变模糊了：细腻的纹理被抹平，渐变出现色带，边缘沾上一圈淡淡的方块。

所以一个大小限制就是一份细节预算。真正有用的问题不是“我能不能压到 500 KB”，什么数字你总归压得到，而是“为了压到那儿，画面里得舍掉多少东西，这对我要拿它干的事要不要紧”。

两条经验。拍真实场景的照片，人脸、树叶、布料这些，很能藏住压缩痕迹，因为眼睛找不到一块完全平坦的地方去挑那些损伤。截图、图表、logo，或者任何有大片平色和硬文字边缘的东西，会立刻把它抖出来，而且它们本来就该是 PNG 或者 WebP，根本不该是 JPEG。

为什么没有公式，以及该拿它怎么办

没有办法算出哪个质量设置会产出一个 500 KB 的文件。这两者之间的关系完全取决于画面里有什么：同样的设置下，一张拍白墙的照片可能只有一张拍森林的照片的十分之一大。任何给你一个“质量：60”然后祈祷的工具，都是在替你猜。

唯一靠得住的办法是试。编码一遍，看看大小，调一调，再编码一遍。手工干这件事很烦，所以压缩工具才改成向你要一个质量数字，那等于把烦人的部分甩给你。自动干这件事大约是八次编码，而在这十年造出来的任何一台机器上，把一张手机照片编码八次都不到一秒，所以本站这个工具是向你要大小，然后自己去搜。

它报出来的每一个大小，都是一个真实编码出来的文件，不是估算。表单有硬限制时这一点很要紧：一个乐观了 2% 的估算，等于一次被拒绝的上传。

先花质量，再花像素

让一个图片文件变小只有两条路。你可以把同一张画面描述得不那么精确，那是质量。或者你可以描述更少的像素，那是改尺寸。两者不是一回事，而且顺序有讲究。

质量在前，因为对一张照片来说，最初大约 30% 的质量下降是真的看不出来的，你扔掉的那些细节，本来就存得比任何眼睛能核对的还要仔细。像素在后，因为质量一旦降到瑕疵开始显形的程度，一张质量尚可的小图就比一张被毁掉的全尺寸图好看。少一些好像素，胜过多一些坏像素。

整个策略就是这个，而且哪怕你用的是别的工具，它也值得知道：把质量往下调，调到开始看着不对劲，然后改成把图片变小，而不是接着往下调。

什么时候该主动改尺寸

有时候那些像素本来就用不上。一张 4000 像素宽的照片，摆在网页上一个 600 像素宽的栏里，带着的细节是任何人看得到的六倍。你要是知道这张图片最终待在哪儿，先把它缩到那个尺寸，大小问题往往就自己消失了，一分质量都没花。干这活儿的工具是图片缩放，而它自己那篇指南讲了怎么挑尺寸。

挑一个格式

有三个格式值得知道，而浏览器三个都能写。

  • JPEG 是给照片的。它有损，它被有史以来的每一样东西认得，而对一张拍真实场景的照片来说，它至今仍是一个很好的选择。它存不了透明。
  • WebP 干的是同一件事，只是干得更好，在你分辨不出的质量下比 JPEG 小大约 25–35%，而且保留透明。现在的浏览器个个都读它。少数老一点的桌面程序和一些企业上传表单至今不认，这也是不用它的唯一真正理由。
  • PNG 无损，也就是又精确又大。截图、logo、线稿，以及任何有锐利边缘或者平色块的东西，用它是对的；照片用它就错了。

要文件的那个人没给你什么限制，WebP 能让你在更小的可见损伤下够到目标。这个文件要进某个老东西，或者进一个你没法测试的系统，那 JPEG 才稳妥。

为什么你的 PNG 小不了多少

这是最常见的意外，而它不是你用的那个工具的 bug。PNG 是无损格式，存的是精确的像素，也没有质量旋钮可拧，拧了它就成了另一个格式。一个 PNG 压缩器能做的全部，就是把同样这些像素打包得更巧妙一点，通常也就值百分之几。

所以，你要是既非要一个小得多的文件、又非要它还是 PNG，剩下的杠杆只有尺寸，也就是更少的像素或者更少的颜色。它可以不再是 PNG 的话，那就看里面装的是什么。

  • 一张存成了 PNG 的照片。非常常见，通常是无意的，也是这一页上最容易的一笔收益：把它转成 JPEG 或 WebP，往往能小五到十倍，而且看不出变化。
  • 一张截图或者一张图表。转成 WebP，你要它无损时它也能无损，而且同样的像素通常比 PNG 小。转成 JPEG 会让文字边缘发毛。
  • 一个带透明的 logo。WebP 会保住那份透明；JPEG 会拿一个实色把它填上，而那几乎从来不是你想要的。

怎么判断结果够不够好

盯着缩略图什么都说明不了，缩略图尺寸下什么都看着挺好。两个更靠谱的检查。

按原尺寸看，看画面里最平坦的那块东西。天空、皮肤、刷过漆的墙。压缩损伤最先在平滑的渐变里显形，表现为淡淡的方块或者色带，而那远早于它碰到细节丰富的区域。

工具给了你一个数字，就读它。这里的压缩工具会把自己的结果解码出来跟原图比，并报出 SSIM，那是一个比较局部亮度、对比度和结构的数字，而不是数有多少像素变了，比后者更接近眼睛真正会挑剔的东西。大约 0.98 以上，两张图并排看很难分开；低于 0.95 左右，发出去之前先自己看一眼。想要传统分贝值的，它还会报 PSNR。

两个都在你自己的机器上算出来并显示给你看，它们存在的意义也就在这儿，把“质量损失极小”从一句断言，变成一个你可以核对的数字。

发出文件之前值得知道的三件事

压缩会顺带清掉元数据。重新编码就是把图片解码成像素、再把这些像素编码一遍，而一张装满像素的画布不带任何标签，所以 GPS 位置、相机型号、时间戳以及其余的一切，根本没被写进新文件。通常这算白赚。你要的是去掉标签但不动画面的话，那是另一件事，EXIF 查看与清除只重写容器，什么都不重新压缩，它那篇指南讲了里面到底有什么。

别把同一个文件压两遍。每一次有损编码都会永久扔掉细节，而对一张已经压过的图片再编码，扔掉的更多，还会忠实地把第一遍留下的那些瑕疵保下来，代价是真正的细节。永远回到原图，只压一次。

留好原件。一次有损编码之后没有回头路。不管你发出去的是什么，把你一开始那个文件在某个地方留着。

这些没有一样需要上传

每个浏览器自带 JPEG、PNG 和 WebP 编码器都已经很多年了，就是把一张画布存成图片的那套代码。压缩图片属于技术上根本没理由牵扯服务器的活儿，所以这里的工具也就没有服务器。图片在你自己的机器上解码、编码、测量，而这个页面的 Content-Security-Policy 里，没有一个属于本站的地址可以把它送过去。

确认这一点最省事的办法，在这里在别处都一样，把页面加载出来，断开网络，然后照样压一个。它还能用，就说明什么都没上传。把文件传给在线转换器安全吗？还列出了另外三个这样的检查。
