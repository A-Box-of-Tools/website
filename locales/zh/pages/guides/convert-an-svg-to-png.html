短答案

打开 SVG 转图片，把文件拖进去，说一个尺寸。如果没人告诉过你该用多大，最长边 1024 像素是个好用的默认值：大到几乎什么用途都够，小到还能用邮件发。格式保持 PNG，背景保持透明，把文件拿走。

下面全部内容，是给这个默认值不够用时准备的 — 别人给你指定了一个数字的时候、它要拿去打印的时候，或者它出来看着不对的时候。

为什么尺寸由你决定，而不是由文件决定

一个 JPEG 是一格一格量好的像素；问它有多大，是有答案的。而一个 SVG 根本不是一张画面，它是一组指令 — 在这儿画一个圆，用那个颜色画这条路径 — 而指令没有尺寸。浏览器可以按 16 像素执行它们，也可以按 4000 像素执行，两边一样锐利，因为它没有在缩放任何东西。它是在重新画。

这就是为什么转换没法替你挑一个数字，也是为什么你挑一个大的不用付出任何代价。这是图片处理里唯一一件“做大点”是免费的事。

大多数 SVG 文件确实带着 width 和 height 属性，工具也会把它显示出来 — 但那是一个默认值，不是一个上限。一个写着 width="24" 的图标，只说明画它的人当时心里想的是一条 24 像素的工具栏。

那个数字究竟从哪儿来

用于网站。拿这张图在页面上占据的 CSS 像素尺寸，乘以你在乎的那些屏幕的像素密度。一个放在 200 像素宽槽位里的 logo，Retina 笔记本需要一个 400 像素的文件，近几年的手机需要 600。@2x 和 @3x 的全部含义就是这个，而这也是为什么一个会替你写出它们的工具，能省下你算三遍。

用于应用图标、商店素材或 favicon。那个数字是公布过的，没什么可算的：商店页面写多少就是多少，一分不差。至于 favicon，根本不要栅格化 — 做一个 .ico，它在一个文件里装着好几个尺寸，因为浏览器标签页、书签和 Windows 快捷方式要的尺寸都不一样。

用于打印。把以英寸计的物理尺寸乘以打印机的分辨率。一个印在名片上、两英寸宽、300 DPI 的 logo 是 600 像素；同一个 logo 铺满 A4 页面，也就是 8.3 英寸，大约是 2500。印刷厂照例要 300 DPI，而对一条隔着房间看的大幅横幅来说，150 绰绰有余。

用于社交预览或 OG 图。平台给出一个框 — 大多数链接预览是 1200 × 630 — 而这个框和你的 logo 形状不一样。那正是“补白”这个设置的用途：图按自己的比例居中，剩下的用一个背景色填上，而不是一个拉变形的 logo，那等于告诉所有人你没检查。

当上面两条同时适用时，取更大的那个。一个比需要的更大的 PNG，无非是下载稍微大一点；而一个太小的 PNG 事后补不回来，理由在下一节。

你回不去了

栅格化是单向的。一旦这幅图成了 PNG，它就和其他任何图片一样是像素了，而事后放大它就不得不编造当初根本没被量过的细节 — 和放大一张照片得到的那种发软、糊掉的结果一模一样。

所以留着那个 SVG。它是母版，它几乎总是更小的那个文件，而且未来每一个尺寸都能从它身上完美地出来。PNG 是给某一个具体用途的一次导出，而当你需要另一个尺寸时，正确的动作是再导一次，而不是去缩放你导出来的那个。

有软件声称能把 PNG 转回 SVG。它做的事叫描摹：猜哪些曲线可能解释得了这一格一格的像素。它在平坦的双色图稿上勉强能用，在其他任何东西上产出的是昂贵的胡说，而且它永远找不回原来那幅图拥有的东西。

它一变成像素，就有三件事变了

一个栅格化出来看着不对的 SVG，几乎总是因为下面三个理由之一，而这三个都值得在导出之前而不是之后知道。

文字是用这台机器上有的字体画的。一个含有文字的 SVG 并不含有那个字体 — 它只是写下一个名字，剩下的交给渲染器去找。如果那个字体没装，就会用一个替代品，而替代品的字形不同、字宽也不同，所以文字可能重排或者溢出。一个从网址拉字体的文件下场更糟：透过 <img> 栅格化的 SVG 根本不被允许请求任何东西，所以什么都不会到。

解法是每个设计师都已经知道的那个：导出 SVG 之前先把文字转成轮廓（Illustrator 叫“创建轮廓”，Figma 叫 Flatten，Inkscape 叫“对象转路径”）。那些字母变成几何图形，字体不再要紧，画面在每台机器上都一样。请在副本上做 — 转成轮廓的文字不再能当文字编辑。

发丝线变灰或者消失。一条在你所选尺寸下算下来不到一个像素的描边，没法被画成一条实线，所以它被画成了一条很淡的线。这就是为什么一个精致的 logo 在 64 像素下栅格化出来像被水冲过，而同一个文件在 512 下看着完美。如果小尺寸是硬要求，答案是一幅笔画更重的简化版图稿，而不是换一个导出设置 — 这也正是 favicon 该是一个符号而不是一个文字标的同一个理由。

动画停了。一个带动画的 SVG 栅格化出来是一张静帧：第一帧是什么就是什么。没有哪个导出设置能改变这一点。如果你要那份运动，你需要的是一张 GIF 或者一段视频，做法完全不同。

透明，以及该挑哪个格式

没有特别理由就选 PNG。它无损，保留透明，而带硬边缘的纯色块 — 也就是一幅图的大部分内容 — 在它里面压得很好。一个栅格化出来的 logo，做成 PNG 通常比做成 JPEG更小，也更干净。

JPEG 根本没有透明。每一个透明像素都得变成某个颜色，而如果没人替你挑一个，它就变成黑的 — 那就是“logo 落在一个黑方块上”这个结果的来历，人们通常以为那是个 bug。它还恰恰在这类画面上表现出最明显的有损：每一条硬边缘周围一圈麻点。只有在某个地方非要它不可时才用它。

WebP 做到 PNG 做到的一切，文件更小，而且当前每一个浏览器都读它。不用它的理由在于浏览器之外发生的事：老一点的软件、某些印刷厂，以及相当一部分上传表单，至今打不开它。

用 PNG 时也挑一个背景色，同样是完全正常的需求。只有当这张图要落在一个你无法预料的颜色上时，透明才有用；而当你已经知道那是一张白色页面时，压平到白色能避开一整类意外。

导出结果是空白或者不对时

除了一片空白什么都没有。通常是根元素上缺了 xmlns 属性。就一个 image 标签而言，一个没有它的文件不算 SVG，画出来就是什么都没有。快速测试是用浏览器打开这个文件：如果浏览器也什么都不显示，那问题在文件，不在转换器。

图很小，缩在左上角。这个文件有 width 和 height，但没有 viewBox，所以没有一套坐标系可以缩放，图稿就在一张更大的画布上保持了它原来的单位。一个好的转换器会替你补一个 viewBox；如果你用的那个没补，手动给根元素加上 viewBox="0 0 宽 高" 就能解决，而这个文件是纯文本，你完全做得到。

画面缺了一块。文件里有什么东西指向了一个地址，而不是把图稿装在里面 — 一张以链接形式存放的内嵌照片、一份样式表、一个字体。一个拒绝去取这些东西的栅格化器做得对，而这也正是那道让一个你从别处下载的 SVG 没法向它的作者回报的同一道拒绝。请在绘图软件里重新导出，并把图片内嵌进去。

它拒绝一个非常大的尺寸。浏览器给画布的大小设了上限，而且各家的上限并不一致：超过大约一条边 16,000 像素就什么都返回不了，而 iPhone 和 iPad 上的 Safari 放弃得早得多，大约在 4096 × 4096。一个会提醒你的工具，是在把你从一个空白文件里救出来，因为浏览器撑不住时给出的正是一个空白文件，而不是一条错误信息。

这些没有一样需要上传

栅格化 SVG 是每个浏览器一天要做几千次的事 — 那就是把一个图标画到网页上的同一套机器。你的图稿没有任何技术上的理由要跑一趟服务器再回来才能变成 PNG，而这里的工具也没有把它送去任何地方：这个页面的 Content-Security-Policy 列出了它可能联系的每一个地址，其中没有一个属于本站。

而这一点在 SVG 上比平常更要紧，因为 SVG 是一份文档，不是一张画面。它可以含有一段脚本和一个远程地址，而一个代理商发给你的 logo，是一个不是你写的文件。透过 image 标签绘制时，它处在规范所说的安全静态模式：脚本跑不起来，那个地址也从不会被联系。执行这一点的是浏览器，不是这个网站。
