Connect the devices and choose the tab

Open the website in one tab and Share a Browser Tab in another on your computer. Both devices need a reachable Wi-Fi, Ethernet or hotspot network. Automatic offers online invitations unless the browser reports that it is offline. Open Connection options to choose Online for an internet introduction and a viewer link, or Offline to exchange connection blocks yourself. Then click Choose a tab to share and select the website tab in your browser's own picker. Choose a browser tab, rather than a window or your whole screen: this tool refuses those broader sources. Check the local preview before sending the link.

In Online mode, choose Copy viewer link and send it to the other person. They open it, read the connection notice, optionally add a short introduction and choose Request to watch. Return to the sharing page to approve the request you expect. The connection first carries only encrypted control messages; video begins after your approval and the viewer's acknowledgement. One viewer can watch at a time, with up to four online requests waiting.

Work in the selected website tab while keeping the sharing page open. A current desktop Chrome or Edge browser is the intended host. The viewer needs a browser that can play WebRTC video, without an extension or an account on the website you show. Online pairing needs internet for its introduction. The video connection itself uses host addresses, with no public STUN service or internet relay in either method.

The browser's network indication is only a hint; it does not test the introduction service or the connection between your devices. An opened viewer link keeps online pairing. An explicit choice in Connection options stays selected when that indication changes, and the method stays fixed while a capture or connection attempt is active.

Find a nearby tab without copying its link

In Online mode, the host can check Show in nearby shared tabs before choosing a tab to share. It is off by default and cannot be changed during a session. The list shows the random invitation code, never the captured tab's title, address or picture.

On the viewer, choose Find nearby tabs and select the host's code. This only fills the invitation; choose Request to watch when ready. The host still approves the request, and your browser acknowledges that approval before any video arrives. Stop sharing removes the host from the list.

Nearby discovery needs internet. The service groups this tool's pages by public IPv4 address or IPv6 /64 subnet and website origin. It does not scan Wi-Fi or prove that someone is physically nearby. A shared carrier gateway or VPN can include strangers, while different routes can hide a device beside you. Confirm the code with the host and use the copied viewer link if it is missing. Offline pairing has no nearby list and uses the block exchange below.

Pair offline on the same Wi-Fi or hotspot

Prepare both devices before losing internet. Open this HTTPS tool on each and wait for each offline indicator to say ready. The tool can then open from its saved browser cache. Keep the website you want to show loaded too, or use a website that works offline. Choosing Offline cannot make an unavailable website load.

Connect the devices to a reachable Wi-Fi, Ethernet or hotspot network yourself. Automatic may already show the offline controls; otherwise, open Connection options and choose Offline — exchange connection blocks on both pages. This page does not create a hotspot, Wi-Fi Direct or Bluetooth link. A hotspot can work without internet if it allows its devices to reach each other; client isolation can prevent that.

  1. On the host, choose the tab and wait for the Host connection block.
  2. Copy that block or save it as a file, then transfer it to the viewer using an available local method.
  3. On the viewer, paste or load the host block, optionally add a note and choose Create viewer reply.
  4. Return the Viewer reply block or its saved file to the host.
  5. On the host, paste or load that reply and choose Connect viewer. When the request appears, approve the viewer you expect.

Keep both pages open during the exchange. The blocks contain network addresses and other connection information, so send them only to the intended person. File controls let you use your operating system's local transfer options, such as Bluetooth or USB; the tool does not transfer those files for you. Remove saved blocks when no longer needed. An expired or mismatched exchange needs fresh blocks.

Offline pairing opens no introduction-service connection and uses no public address-discovery service or relay. Establishing the connection still sends no video: the separate host approval step remains. One offline exchange connects one viewer, and another viewer needs a fresh exchange.

What the viewer can see and do

The viewer sees a live video picture. Your scrolling, page navigation, menus and visible account content in that tab become part of the picture. Simply activating another browser tab does not select a new capture source, but anything you reveal inside the selected tab is shared. Check the browser's capture indicator and stop before opening private information there.

The viewer's clicks and typing cannot operate your browser. They do not receive your login cookies or a working copy of the website. Text in a video is not selectable, so this version cannot provide webpage copying. Use Share Text & Files alongside it when the other person needs a link, note or file they can copy. Some protected content may be black or unavailable in a capture.

No audio is requested or sent, including tab sound. The tool does not request camera or microphone access and makes no recording. A viewer can still record their own view or take screenshots. Ending the link stops future video; it cannot erase anything already kept.

The invitation permits a request; your approval permits video

Online sessions have fresh random links; offline sessions have fresh connection blocks. An online host may choose to publish its invitation code in the nearby list; this is off by default. Anyone who obtains an invitation can attempt a connection, including its network-address exchange. They still need your approval for video. The name or note they type is not verified identity, so recognise the person through the conversation you already have and approve only the request you expect.

A URL fragment does not hide a link code from scripts running in the same page, and a browser may keep its history. Pasted connection blocks are also visible to same-page scripts. The tool page has the site's usual advertising, measurement and donation scripts. The tool does not deliberately send them video or notes, but same-page scripts can read the page's address and state. Mandatory approval remains the admission step.

How the video reaches the other browser

In Online mode, a small introduction service matches the browsers through the random code and forwards WebRTC setup messages. It sees the code, addresses, connection times, descriptions and connection candidates. Setup is not hidden from that service. Optional nearby discovery also publishes the room code to the service's network group, without the tab title, address or picture. The video, viewer note and approval decisions do not pass through it. Cloudflare keeps connection request metadata for seven days. The service writes no room content to storage. Offline mode uses only the exchanged blocks and does not contact that service.

Both methods use a direct encrypted WebRTC connection with no STUN server or TURN relay. Setup accepts only the browsers' host connection addresses, and each browser learns addresses from the other before video approval. Host addresses can include public interfaces or follow a VPN route; this policy does not prove that traffic stays inside a building.

Guest-network or hotspot isolation, firewalls, VPN routes and browser local-network permissions can block the connection. Sharing a Wi-Fi name alone does not establish reachability. Try the actual network before a demonstration or support call. Neither method falls back to an internet relay, and online pairing is not a promise of continuity when its internet connection disappears.

If the introduction service cannot connect, Automatic offers offline controls for a new attempt. You can also choose Offline under Connection options. The host must start again, choose the tab again and exchange fresh blocks with the viewer; the previous viewer link cannot become an offline block. No capture, reply or connection starts automatically.

Keep both host tabs open, then stop deliberately

Hiding the sharing page keeps healthy capture where the browser permits, which lets you use the selected website tab normally. Keep both tabs open and the device awake. Sleep, a closed laptop or browser suspension can interrupt or end the stream; this page cannot override those policies.

Choose Stop sharing on the tool page or use your browser's capture control when finished. Closing the sharing page or ending the captured tab also ends the source. If capture ends, returning to the page never silently captures again. Start again, choose a tab again and send the new invitation or connection blocks. A new viewer always needs fresh approval.
