Start on the speaking device

Open Local Walkie-Talkie on this website and enter a Channel name that listeners will recognize. Keep Show this channel nearby selected to list it, or clear it to invite people only by link. Choose Start channel and allow microphone access. A supported phone or computer can host through the HTTPS page. There is no Python helper, download or account. For the most reliable connection, keep the host page visible and its device awake when possible.

Find a channel or invite listeners

Listeners open Local Walkie-Talkie and select a channel with Choose in Nearby channels at the top, then choose Join channel to connect. The list updates automatically. Choosing alone does not connect; joining is receive-only and never requests microphone access. If the channel is not listed, share its listener link or QR code instead; opening an invitation starts connecting automatically. If the browser blocks sound, Unmute starts it. Once connected, listeners use Mute/Unmute and Leave.

Online mode needs internet access for discovery and pairing. The service carries channel names, listener invitations, connection details and status; live voice takes a separate direct encrypted route from the host to each listener. There is no public audio relay fallback.

Nearby discovery groups browsers by their public IPv4 address or IPv6 /64 and this website's origin. It does not scan Wi-Fi or prove that a listed channel is on your physical network. Shared gateways can include strangers; VPNs and different internet routes can hide devices beside you. Use the listener link when discovery misses a channel.

Pair without internet

Load the page on both devices first, then select Offline. Start the host, give its invitation block to one listener, and paste that listener's reply on the host. Listening starts after the host accepts the reply, without microphone access on the listener. Use a fresh invitation for every additional listener. You can copy the blocks or transfer their saved files. Both devices still need a reachable Wi-Fi or hotspot route. Keep the tabs open: if the direct signaling connection closes or a page reloads, exchange new blocks. There is no internet discovery, pairing socket or audio relay in Offline mode.

Hold to talk

Hold the Talk button with touch or a mouse, or focus it and hold Space. Release to stop sending voice. For hands-free speech, choose Start talking: voice keeps transmitting until you choose Stop talking. Check the displayed talking state before setting the device down. Microphone mute overrides both modes. Up to ten listeners may connect, including waiting connections; begin with a small group and check the devices and network you intend to use.

Recover a lost host

Waiting receivers check host availability in place with a one-second foreground target and keep their mute choice. Working direct voice can continue during a brief pairing-service outage. Background browsers, service connection limits and sleeping devices can delay recovery.

Hiding the page keeps a healthy connection open. A held Talk button is released; hands-free speech started with Start talking can continue while the browser allows it. Phones may still suspend the microphone, playback or network when locked. An actual microphone interruption stops talking while keeping the channel open. On return, the page tries to replace an ended microphone; choose Resume microphone if needed. After page suspension, it tries to restore the same channel and invitation; choose Resume channel if the browser requires an action. Talking stays off after an interruption until you start it again.

In Online mode, temporary per-tab browser storage lets a reload retain the channel too; when storage is unavailable, a host reload creates a new invitation. End broadcast removes the listing and deliberately stops the session. It prevents automatic resumption, and the next Start creates a fresh invitation. Leave stops one listener and its retries.

Share invitations carefully

A listener invitation gives access to live audio to anyone who has it and can reach the host directly. Starting with Show this channel nearby selected intentionally shares the channel name and listener invitation key with its discovery group. Anyone who finds it can join and listen. Clear that option before starting if you want to share invitations only by link. The host's separate key stays in its browser tab and is not shared. For copied links, listener keys travel in the fragment after the # character, then in secure pairing messages. The service keeps temporary room state on open connections; Cloudflare retains seven-day invocation metadata logs, never microphone audio.

The website's regular advertising, measurement and donate-button scripts run on this page. The tool does not hand them audio, but page scripts can read the address and browser storage. Removing an invitation fragment where storage is available reduces its later exposure; it does not isolate those scripts. Trust the page before granting microphone access. Recipients can independently record what they hear.

Check reachability

A phone hotspot can work when it lets the participating devices reach one another directly. Connect the devices to the same hotspot and use Online for internet discovery and pairing, or Offline for exchanged blocks. Use the listener link or QR code if the nearby list misses the channel. Some hotspots and managed devices block direct traffic, so test your actual devices before relying on it.

Guest Wi-Fi can isolate devices. Firewalls, browser local-network permissions, VPNs and operating-system routes can affect direct connectivity even when two devices appear to share Wi-Fi. The tool uses host candidates only and no STUN or TURN server; that limits the route without proving a physical network boundary. Try the actual phones and computers before relying on the channel.
