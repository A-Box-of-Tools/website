Start on the speaking device

Open Local Walkie-Talkie on this website, choose Start channel and allow microphone access. A supported phone or computer can host through the HTTPS page. There is no Python helper, download or account. Keep the host page visible and its device awake.

Invite listeners

Share the listener link or QR code with devices on your reachable Wi-Fi or Ethernet network. Opening the invitation starts connecting automatically and never requests microphone access. If the browser blocks sound, Unmute starts it. Mute/Unmute and Leave are the only listener controls.

Both sides need internet access for pairing. The service carries connection details and status; live voice takes a separate direct encrypted route from the host to each listener. There is no public audio relay fallback.

Hold to talk

Hold the Talk button with touch or a mouse, or focus it and hold Space. Release to stop sending voice. Start talking offers click-to-start and click-to-stop. Microphone mute overrides both. Up to ten listeners may connect, including waiting connections; begin with a small group and check the devices and network you intend to use.

Recover a lost host

Waiting receivers check host availability in place with a one-second foreground target and keep their mute choice. Working direct voice can continue during a brief pairing-service outage. Background browsers, service connection limits and sleeping devices can delay recovery.

Hiding the host page releases its microphone. Return to the same tab and choose Start channel to resume its retained invitation. Temporary per-tab browser storage lets a reload retain the channel too; when storage is unavailable, a host reload creates a new invitation. End broadcast deliberately stops the session and the next Start creates a fresh invitation. Leave stops one listener and its retries.

Share invitations carefully

A listener invitation gives access to live audio to anyone who has it and can reach the host directly. The host's separate key stays in its browser tab and is not shared. Listener keys travel in the link fragment after the # character, then in secure pairing messages. The service keeps temporary room state on open connections; Cloudflare retains seven-day invocation metadata logs, never microphone audio.

The website's regular advertising, measurement and donate-button scripts run on this page. The tool does not hand them audio, but page scripts can read the address and browser storage. Removing an invitation fragment where storage is available reduces its later exposure; it does not isolate those scripts. Trust the page before granting microphone access. Recipients can independently record what they hear.

Check reachability

Guest Wi-Fi can isolate devices. Firewalls, browser local-network permissions, VPNs and operating-system routes can affect direct connectivity even when two devices appear to share Wi-Fi. The tool uses host candidates only and no STUN or TURN server; that limits the route without proving a physical network boundary. Try the actual phones and computers before relying on the channel.
