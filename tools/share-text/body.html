Local shares on this connection

Looking for local shares…

This list shows link names from browsers using the same public IPv4 address or IPv6 subnet as yours. Usually that means the same router; a shared VPN or an ISP sharing one address can include other networks. Mixed IPv4 and IPv6 connections or different routes can hide nearby devices. Internet is required. Opening a share still asks before connecting, and Private shares still need the sharer’s approval.

1 Write it, or attach it

Files ride the same direct connection as the text, up to 200 MB apiece, with up to 256 files in one share. Readers see the list and fetch each file only if they ask for it.

2 Name the link

The name is the address, short enough to say across a room. Discoverable local shares list it for others on this connection. Keep Private on for anything sensitive.

For devices on the same Wi-Fi or Ethernet. Internet is still needed to introduce the browsers; this mode uses no public address-discovery server or relay. VPNs and browser settings can affect the network path. The copied link carries this setting. Local network is off by default; choose it to list your share in local discovery.

About discoverable shares

A discoverable share lists its name for others using the same public IPv4 address or IPv6 subnet. Keep Private on, especially on shared networks. With Private off, anyone who sees the name can connect and read without your approval. Uncheck Discoverable to share only by link.

The draft is kept only in this browser, so it is still here next time — unless you mark it one-off, in which case nothing is kept anywhere at all.

3 Share it

Nothing is stored anywhere

The text and the files travel straight from this tab to each reader’s, encrypted. The rendezvous introduces the browsers and lists discoverable link names; it never sees the text or files. Closing this tab ends the share and clears readers’ open pages too — though what someone already copied or downloaded is theirs.

Someone is sharing with you

Looking for the sharer…

Connecting lets the sharer send the text and files straight to your browser over an encrypted channel. Like any direct connection, it lets each side see the other’s network (IP) address. The sharer does not learn that you opened this link until you choose to connect.

This link uses Local network mode. Both devices need to be on the same Wi-Fi or Ethernet, and internet is still needed for the introduction. No public address-discovery server or internet relay is used. VPNs and browser settings can affect the network path.

Tell the sharer something they’ll recognise — a name, a hint — and they can let you in. Your message goes straight to their browser.

The alternative is an encrypted relay. Your browser would send and receive through a relay server run by Cloudflare, which forwards the encrypted bytes and cannot read them; it learns your network address and the sharer’s, as the direct connection would have. Nothing is stored there either, and the sharer’s page still sends to you alone.
